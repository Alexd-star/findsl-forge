## 一、当前项目类型判断

| 项目类型 | 判断 |
|---|---|
| 算法赛题 | 是。项目核心包含 DSL 解析、AST、语义检查、SQL 生成、prefix-sum 优化和等价验证。 |
| 深度学习项目 | 否。项目没有训练日志、模型权重、loss 曲线、mAP、混淆矩阵等深度学习材料。 |
| 机器学习/数据建模项目 | 否。NL2DSL 只是候选生成入口，不是模型训练或预测建模项目。 |
| 数据库/Doris/SQL 优化项目 | 是，且是最核心类型。赛题要求把行情选股 DSL 编译成高性能 Doris SQL，并证明长窗口查询加速。 |
| Web/软件系统 | 是。项目提供本地 Web Demo/API，展示 DSL、AST、SQL、Explain、Rows、Evidence 和 Diagnostic。 |
| 数据处理/自动化脚本项目 | 是。项目包含 evidence export、Doris asset 生成、readiness、benchmark、截图证据包生成脚本。 |
| 嵌入式/STM32/硬件控制项目 | 否。无硬件、传感器、串口、控制环路。 |
| Verilog/数字电路/仿真项目 | 否。无 HDL、testbench、波形文件。 |
| 科研计算/论文复现实验项目 | 部分相似。项目有可复现实验和性能证据，但目标是工程竞赛交付，不是论文复现实验。 |
| 课程设计/综合工程项目 | 是。代码、文档、测试、Demo、证据包、答辩材料形成综合工程交付。 |

项目类型：数据库/Doris/SQL 优化项目 + 编译器算法赛题 + Web/软件系统 + 自动化交付工程。

判断依据：README 明确写明 Topic 19 是“Compile stock-screening DSL into high-performance Apache Doris SQL”；核心链路为 `DSL -> Lexer/Parser -> Typed AST -> Semantic Validation -> SQL Plan -> Doris SQL`；证据摘要包含 Doris evidence、Doris speedup、official suite、pytest 和 Web Demo 截图。

最需要证明的内容：

1. 赛题理解正确：输入是中文需求/DSL，输出是可审计 Doris SQL、AST、Explain、验证结果和提交证据。
2. 编译链路可信：不是让 LLM 直接写 SQL，而是确定性编译器、语义检查和 SQL/reference 等价验证。
3. 长窗口优化有效：baseline window 与 prefix-sum 优化结果行数一致，Doris 证据显示 36.24x speedup。
4. 测试和审计扎实：pytest 311 passed，官方正例 37/37，官方负例 37/37，Blocking gates PASS，Warning count 0，Metadata warnings `<none>`。
5. 交付完整：文档、脚本、Demo、Doris assets、截图证据包、Git 回溯状态齐全。

最适合的图表类型：

- 系统架构图、数据流图、编译管线图、算法流程图、执行计划对比图、性能柱状图、speedup 指标卡、测试验证仪表板、赛题要求映射矩阵、交付包结构图。

不适合的图表类型：

- Loss/Accuracy 曲线、混淆矩阵、ROC/PR 曲线、mAP 曲线、Grad-CAM、模型结构图、硬件连接图、Verilog 状态机/时序波形图。这些没有项目数据来源，不能为了视觉效果强行绘制。
