# 赛题要求与验收

## 1. 赛题要解决的问题

行情选股 DSL 是面向业务人员的结构化查询语言。系统需要把函数、指标、日期、市场范围、排序和集合逻辑翻译为可在 Apache Doris 上执行的 SQL，并保证结果含义正确、长周期查询足够快、新指标和函数容易扩展。这里的核心不是“把字符串替换成 SQL”，而是完成一条可诊断、可优化、可复核的编译链。

输入是官方七槽位 DSL 及其复合表达式；输出至少包括 Doris SQL。完整工程还应输出类型、语义、数据范围和物理计划诊断，使无法可靠处理的输入得到明确错误，而不是生成看似合法但结果错误的 SQL。

## 4. 隐含验收要求

1. **语义优先于表面覆盖率。** 缺少指数成员、行业归属、分钟行情或事件数据时，必须返回数据不可用诊断，不能把范围替换成全市场或空集合。
2. **优化前后必须等价。** 只看 SQL 能执行或行数相同不够，需要比较完整结果、顺序规则和 SHA-256，并固定数据快照。
3. **性能实验必须可解释。** 基线和优化查询使用同一语义、同一数据、同一缓存策略和重复次数，报告 P50/P95、EXPLAIN/Profile 和结果一致性。
4. **扩展能力必须做盲测。** 新配置应由不了解核心实现的测试新增，确认不修改 parser、binder、planner 和 backend 仍可工作。
5. **错误必须稳定。** 非法输入、歧义语义、缺失数据和系统故障要使用不同错误码，并给出源位置和修复建议。
6. **证据必须绑定版本。** 每个评分数字应带 Git HEAD、数据指纹、配置指纹、Doris 版本和生成时间。
7. **规划过程必须可解释。** `FINDSL EXPLAIN` 应同时展示查询特征、候选可行性、成本、最终路由和回退原因，不能只给最终 SQL。
8. **历史成员关系必须按日期生效。** 行业、概念、指数成分和交易规则同时受快照与有效期约束，不能用当前成员回答历史查询。
9. **加速数据过期必须回退。** PREFIX/MV 水位与基础表不一致时不能参与正式选路，即使其估算成本更低。
10. **支持边界必须可协商。** 单条 DSL 应明确区分支持、缺数据、输入无效和能力缺口，不能把所有拒绝都包装成编译失败。

## 5. 明确边界

- 53 条旧成功集迁移缺口仍受 57 个范围目标影响；其中有歧义名、疑似噪声、赛题域外资产和缺少版本化成员关系的数据，不能用模糊匹配补数。
- 配置式函数模板覆盖可由现有类型化物理算子组合的新函数；需要全新窗口或关系语义时，应增加受审计插件节点，不能宣称任意新语义都只改 JSON。
- `48/48 <10s` 和五类长周期矩阵只证明冻结工作负载，不代表任意并发、硬件或未来数据规模都满足同一时延。
- 最终证据由统一脚本在冻结提交上重采，全部 JSON 同时校验 Git HEAD、数据快照与评分门禁。

## 6. 满足的判定方式

一项要求只有在“代码已实现、测试能捕获回归、真实 Doris 执行通过、独立结果一致、证据绑定版本”五个条件同时满足时才标记完成。计划和文档描述不算实现，解析成功不算业务正确，单次快跑不算 P95，历史最好数字不算当前性能。
