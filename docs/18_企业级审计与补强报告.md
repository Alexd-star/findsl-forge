# 18 企业级审计与补强报告

本文档记录 2026-06-07 对 FinDSL Forge 的功能、代码、框架、算法、实现和交付材料进行的企业级审计。审计目标不是重复说明已有功能，而是检查项目是否存在原理错误、代码误用、安全边界薄弱、材料口径漂移、基础版应付痕迹或尚未达到顶尖交付水准的部分，并记录已经完成的补强。

## 1. 审计结论

本轮审计未发现 DSL 解析、语义校验、SQL 生成、reference 等价验证、prefix-sum 优化、Doris 证据采集主链路存在原理性错误。项目整体不是简单 Demo 或应付版，已经具备清晰的编译链路、独立参考语义、官方风格正负例、Doris 规模证据、Web Demo、中文文档和 Git 回溯。

本轮发现并修复了一个安全边界成熟度问题：Doris SQL validator 原先能识别裸表名，例如 `dwd_stock_daily_quote`，但对 Doris/MySQL 常见的反引号表名和库名限定表名识别不足。若只从当前编译器输出看，该问题不影响已有生成 SQL；但从企业级安全边界看，validator 作为 SQL 安全检查层，应能识别 `` `surprise_table` `` 和 `` `db`.`table` `` 这类常见写法，否则直接验证外部 SQL 片段时可能漏报未知表引用。

## 2. 已补强内容

### 2.1 Doris SQL 表引用识别

修改文件：`src/findsl/doris_sql.py`

补强前，表引用提取逻辑主要匹配：

```text
FROM dwd_stock_daily_quote
JOIN dwd_stock_daily_quote_prefix
```

补强后，validator 同时支持：

```text
FROM `dwd_stock_daily_quote`
FROM findsl_demo.dwd_stock_daily_quote
FROM `findsl_demo`.`dwd_stock_daily_quote`
JOIN findsl_demo.dwd_stock_daily_quote_prefix
```

实现方式是将 `FROM/JOIN` 后的标识符解析扩展为“普通标识符或反引号标识符”，并允许一层库名限定。最终安全判断仍以物理表名为准，因此 `findsl_demo.dwd_stock_daily_quote` 会规范化为 `dwd_stock_daily_quote`，未知表 `` `surprise_table` `` 会被识别并返回 `UNKNOWN_TABLE_REFERENCE`。

## 3. 功能成熟度分析

### 3.1 已达到较高成熟度的部分

编译器主链路成熟度较高。项目从 lexer、parser、typed AST、semantic analyzer 到 SQL generator 的职责边界清楚，非法指标、非法窗口、非法日期、裸字段绕过、rank 参数互斥、静态除零和 LLM 直接 SQL 等高风险输入均有拦截。

正确性验证链路成熟度较高。项目没有只用 SQL 字符串片段证明正确，而是使用 Pandas reference evaluator 和 SQLite executor 做行集等价验证，能覆盖窗口、排名、日期范围、稀疏辅助表、NULL/UNKNOWN 语义等容易失分的细节。

Doris 性能证据链较完整。项目保留了 Doris DDL、prefix 表构建、smoke queries、5,000,000 行规模证据、EXPLAIN 标记、行数一致性和 36.24x 长窗口加速结论。文档中已经明确该性能结论只适用于特定 120 日成交量滚动 SUM 的 prefix 热点路径，不泛化到所有查询。

AI 辅助边界较清楚。NL2DSL 和 LLM provider 都只是候选来源，候选必须进入同一套 DSL 编译、安全校验和 reference 验证链路。直接 SQL 输出会被拒绝，这一点对金融数据库场景很关键。

### 3.2 已发现并补齐的不足

SQL validator 的表引用解析原先偏基础，只覆盖裸表名。该问题已经补齐，并有回归测试。

文档中的测试数量是人工维护口径，新增测试后需要同步更新。当前已经同步到 `192 passed`，但后续仍建议把关键数字集中到一个 evidence metadata 文件或从 readiness 报告自动读取，减少手工漂移。

### 3.3 仍属边界或人工确认的问题

真实行情样本目前只覆盖少量公开 K 线字段，真实资金流文件是中性占位数据。这个不是代码错误，但答辩时必须继续保持边界：真实行情样本用于业务可信展示，5M 合成数据用于性能证明，不应把占位资金流说成真实资金流。

多 BE Doris、生产级 Routine Load、真实 provider 大规模效果评测、更多真实数据源和企业权限体系仍属于后续增强方向。它们不是当前赛题核心链路的缺陷，但如果目标进一步产品化，可以作为下一阶段路线。

## 4. 后续补强优先级

高优先级：将 evidence 数字自动化。建议新增一个轻量脚本，从 `submission_readiness.md`、`official_suite_report.md`、`doris_cluster_evidence.md` 中抽取 pytest、正负例、Doris speedup、warning count 等数字，生成统一 metadata，文档生成脚本只读取该 metadata。

中优先级：给 SQL validator 增加更多 SQL 方言边界测试，例如 CTE alias、子查询、`UNION`、反引号中的转义反引号、非法注释、schema-qualified unknown prefix 表等。

中优先级：扩大真实行情样本覆盖范围。可以增加更多股票、更多日期、更多真实资金流或财务字段，但要确保来源、许可和字段口径可说明。

低优先级：继续改善 Web Demo 的演示体验，例如查询历史、证据下载、配置化指标查看、错误案例对比等。这些能增强展示质感，但不应在提交前替代核心验证。
