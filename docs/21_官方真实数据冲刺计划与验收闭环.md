# 第21章 官方真实数据冲刺计划与验收闭环

本文档记录在拿到官方真实数据之后，FinDSL Forge 还需要怎样继续冲刺。它不是宣传稿，而是给开发、验收、答辩三方共同使用的闭环清单：哪些内容已经被官方资料证明，哪些内容只能在三张 A 股行情表上落地，哪些内容因为官方数据包本身没有对应数据域而不能伪造，哪些工作必须等 Doris 环境真实导入后才能完成。

## 21.1 当前基本判断

当前项目已经从“样例工程”进入“官方真实数据适配工程”。新的主线不再是扩充界面或演示材料，而是围绕官方资料目录中的三类文件闭环：`选股提槽说明.txt` 定义 DSL 规范，`选股提槽实例.xlsx` 提供 5799 条官方训练语料，`Doris A股行情数据集` 提供三张真实 CSV 和建表说明。项目目前能够读取这批资料，生成官方数据画像和覆盖率报告，并且只对官方三表或由三表确定性派生出的特征生成 Doris SQL。

最新复核结果是：官方 workbook 共 5799 条样例，5792 条语法可解析，7 条语法失败。7 条失败不是编译器拒绝正常语法，而是官方语料中存在多余引号、缺少引号、末尾多括号或开头残缺 `and`。在 5792 条语法可解析样例中，1536 条可以落到官方三表或可派生技术特征表上，4256 条不能直接落地。这个比例看上去不高，但它反映的是官方训练语料覆盖了财务、基金、指数成分、用户持仓、龙虎榜、题材热度、相似 K 线等更宽的数据域，而本次真实 CSV 只提供 A 股代码表、行情基础宽表、行情衍生宽表。对缺数据域强行生成 SQL 会变成假输出，反而是答辩风险。

因此，当前完成度应这样表述：编译器内核、官方槽位解析、官方三表字段映射、日期归一化、复合相对日期、单位缩放、窗口聚合、出现/连续次数、rank-count、链式 rank、行业聚合、创新高低/位置函数可落地子集已经完成；真实 Doris 导入、官方数据性能证据、部分函数如 `reset/close_together`、rank 特征表和缺失数据域扩展仍是后续重点。项目还不能说“全部满分完成”，但已经具备面向国家级奖项继续冲刺的可靠工程底座。

## 21.2 官方真实数据解读

官方数据包实际包含三张可执行表。

`hsj_stock_code_info` 是股票基础信息表，共 5686 行、17 列。它提供 `mktcode/tgtcode/name/tztcode` 以及 ST、沪深京 A 股、科创板、创业板、沪股通、深股通、陆股通、所属行业等标志。这个表支撑市场过滤、股票名称展示、行业聚合、板块标志过滤和部分布尔指标，但它不包含概念题材完整成分、不包含指数成分权重，也不包含用户自选股或持仓池。

`hsj_stock_hq_basic` 是行情基础宽表，共 13,650,347 行、56 列，日期范围 2015-01-05 至 2026-04-14。它提供价格、成交量、成交额、换手率、量比、估值、涨跌停、涨停时间、支撑压力、总股本、流通股本等字段。字段以整数缩放存储，价格、估值、比例类字段需要按 10000 缩放到人类可读单位。它是官方 SQL 的主骨架，所有输出默认以这张表的 `mktcode/tgtcode/bizdate` 为股票日期身份。

`hsj_stock_hq_ext` 是行情衍生表，共 6,170,822 行、64 列，日期范围 2019-06-06 至 2026-04-14。它提供 3/5/10 分钟涨速、集合竞价、主力资金流、大小单、筹码形态、创新高低天数、连涨连跌、破板次数等字段。这个表的日期范围晚于基础行情表，因此历史查询在 join 这张表时可能没有记录。编译器使用 left join，并把缺失衍生字段视为真实数据缺失，而不是补零伪造。

官方 workbook 的高频函数和指标说明了评分重点。`indicator` 出现 9831 次，是绝对核心；`rank` 出现 2043 次，说明排名和 TopN 是第二重点；`queryData/cross_above/position/belong_industry/record_high/record_low` 出现次数也足够高，不能完全忽略。高频指标中，“最新价、涨幅、成交量、涨跌幅、主力净流入、涨停、总市值、跌幅、ST股票标识、5日均线、收盘价、20日均线、10日均线、换手率、市盈率、60日均线、成交额、量比、市净率、放量、上涨趋势”等可以由三表或派生特征支撑，是项目必须优先打磨的高分区。相反，“成分股、主营业务、跟踪指数、基金类型、归母净利润、股息率、投资市场、基金十大重仓股、净资产收益率、我的持仓股、龙虎榜”等不在官方三表中，只能做缺失域诊断或等待额外数据。

## 21.3 已完成能力清单

官方槽位解析器已经支持单引号、双引号、百分数、负百分数、布尔值、`and/or/then`、括号优先级、四则运算、函数调用、`between`、`limit` 和官方槽位函数参数。解析结果可以输出 AST，便于说明“系统不是让大模型直接写 SQL，而是先把 DSL 变成确定性语法树”。

官方 SQL 编译器以 `newzl.hsj_stock_hq_basic` 为主表，按需连接 `newzl.hsj_stock_code_info`、`newzl.hsj_stock_hq_ext` 和 `newzl.hsj_stock_hq_basic_technical`。它统一输出 `mktcode/tgtcode/bizdate/name`，并保留 warning，不在 SQL 中插注释。生成 SQL 的核心原则是：只有字段来源明确、单位缩放明确、日期约束明确、表 join 明确，才允许编译成功。

日期归一化已经覆盖今天、今日、当前、昨天、前天、近 N 日、本周、上周、本月、上月、今年、去年、前年、二位年份、中文年份、显式年份区间、`YYYY-MM-DD` 和月日表达，并进一步覆盖“基准区间 + 前/后/第 N 日/周/月/年”的核心复合相对日期。典型例子包括“2006年-12年”“06年到12年”“昨天的前1日”“本月的前一周”“2012年的后4年”“一二年的第4年”“2018年的第五年”“最近的第二天”和“最近的第二天的后3日”。如果窗口超过官方锚点日期，系统会裁剪并保留 warning；如果窗口完全落在官方数据之后，系统输出 `1=0`，不再用 `1=1` 放宽条件。这一点要继续保持，因为日期错比功能少更危险。

单位缩放已经做过真实数据校验。价格类字段统一 `/10000.0`，估值/比例类字段也按官方整数存储口径缩放，涨跌幅通过 `(lastPx - preClosePx) * 100 / preClosePx` 生成。这样“最新价小于 30”“市净率小于 2”“涨幅大于 5%”才符合业务语义。

窗口语义已经覆盖普通指标的 `AVG/SUM/MAX/MIN`、`GROWTH_RISE/GROWTH_FALL`、`EXIST/CONS`，并对 `agg_func + count_exp` 生成按日/周/月/季度/年 bucket 的统计子查询。普通 `rank(..., count_exp)` 已经用 `DATE_TRUNC` 分桶后计算 `ROW_NUMBER()`，再按 `EXIST/CONS` 统计满足排名条件的 bucket 数。

链式 `then rank(...) then rank(...)` 已经完成可落地子集。编译器生成 CTE 管线：`stage_0` 做过滤，`stage_1` 在过滤结果中排名并收窄，`stage_2` 再在上一阶段结果中排名并收窄。这种结构比把多个 rank 条件塞进一个 WHERE 更清楚，也更适合 Doris `EXPLAIN` 展示。当前只支持普通 numeric/time 指标 rank；带时间 count 或聚合的链式 rank 需要后续特征表。

`record_high/record_low` 已优先使用官方衍生表中的 `pxMkTopDays/pxMkBotDays`，避免把窗口函数直接放进 WHERE。`position` 已支持数值指标在指定周期内按最小/最大值划分为 `最低/低/中/高/最高`。`belong_industry` 已支持基于 `hyBlkRefName` 的行业平均、最大、最小、求和聚合。

覆盖率报告已经新增缺失数据域分层。当前剩余失败可以解释为“官方三表未覆盖的其他指标、财务报表数据缺失、公司画像与题材热度数据缺失、指数成分与权重数据缺失、基金产品与持仓数据缺失、高级形态/相似度模型数据缺失、公司事件与交易日历扩展数据缺失、用户账户与自选股数据缺失、函数语义待扩展、交易规则与跨市场标的属性缺失、龙虎榜与交易异动数据缺失、出现次数/连续次数时间语义待特征表增强、排名表达式形态待规范或待扩展、创新高低/位置函数复杂周期待增强、复杂表达式组合待扩展”等类别。

## 21.4 仍需完成的冲刺任务

第一优先级是官方 Doris 真实导入与性能证据。这是当前最大缺口。必须把三张 CSV 通过 Doris 导入，执行 `deploy/doris/official/01_schema.sql`、`02_stream_load.md`、`03_smoke_queries.sql`、`04_feature_tables.sql`，然后生成 `reports/official_doris_evidence.md`。验收标准是三表行数与画像一致，日期范围一致，至少 10 条官方可落地 SQL 能执行，至少覆盖普通过滤、rank、窗口聚合、技术特征表、prefix 特征表五类场景，并记录 `EXPLAIN` 与多轮耗时。

第二优先级是 `reset/close_together` 的可解释阈值实现。官方没有给出“粘合”和“回调”的统一数值阈值，因此不能硬编码一个随意百分比。建议做成配置化策略：默认阈值写入 `configs/official_technical_patterns.json`，文档说明来源和可调参数；SQL 层使用技术特征表中的 MA/支撑压力/价格区间计算，避免临时窗口函数过重。

第三优先级是 rank feature table。带 `rank(..., agg_func, count_exp)` 或链式 rank + 时间 count 的场景，直接在 SQL 中嵌套窗口会很重。建议在 Doris 中建立按日/周/月/年预计算的 rank 特征表，字段包括 `mktcode/tgtcode/bucket_key/indicator_name/rank_direction/rank_no`，再由编译器查表。这样符合高性能主题，也能降低 EXPLAIN 中的窗口代价。

第四优先级是缺失数据域的答辩证据。当前已经做了分类，但还需要把每个大类对应到官方数据包缺失文件：财务报表需要利润表/资产负债表/现金流量表；基金持仓需要基金产品和持仓明细；指数成分需要指数成分与权重；龙虎榜需要交易异动明细；用户持仓需要账户授权数据；公司画像和题材热度需要外部画像或知识图谱。这部分应写入提交说明，避免评委误以为是代码懒得做。

## 21.5 技术依据与实现原则

Apache Doris 的 Stream Load 是本项目导入官方 CSV 的主路径，因为它适合把本地文件通过 HTTP 导入 Doris 表，并且可以拿到同步导入结果，便于做行数验收。官方资料三张表使用 `UNIQUE KEY` 语义，项目在本地证据环境中保留这一模型，并把 `replication_num` 调为 1 以适配单机 Docker。Doris 支持窗口函数，项目用 `ROW_NUMBER()` 实现排名，用 `DATE_TRUNC` 做日/周/月/季/年分桶；对长窗口和重复查询，则通过显式特征表或 prefix 表降低运行期计算量。相关官方资料可参考 Apache Doris 文档：

- [Stream Load 导入](https://doris.apache.org/docs/data-operate/import/stream-load-manual/)
- [Unique Key 数据模型](https://doris.apache.org/docs/table-design/data-model/unique/)
- [窗口函数](https://doris.apache.org/docs/sql-manual/sql-functions/window-functions/)
- [异步物化视图](https://doris.apache.org/docs/query-acceleration/materialized-view/)

实现原则有三条。第一，能由官方三表直接字段化的指标优先直接字段化；第二，能由官方三表确定性派生的技术指标进入特征表；第三，需要额外数据域的指标必须诊断，不生成伪 SQL。这个原则比追求 100% 覆盖率更重要，因为赛题是高性能编译系统，不是字符串替换器。

## 21.6 具体执行顺序

1. 确认本地 Doris FE MySQL 端口 `9030` 和 HTTP 端口可用。
2. 执行 `deploy/doris/official/01_schema.sql`，创建 `newzl` 数据库和三张官方基础表。
3. 按 `deploy/doris/official/02_stream_load.md` 导入 `hsj_stock_code_info.csv`、`hsj_stock_hq_basic.csv`、`hsj_stock_hq_ext.csv`。
4. 执行行数校验：`5686 / 13650347 / 6170822` 必须完全一致。
5. 执行 `deploy/doris/official/04_feature_tables.sql`，构建 prefix 表和 `hsj_stock_hq_basic_technical`。
6. 用 `python -m findsl.cli official-slot-coverage` 重新生成覆盖率报告，确认 `parse_ok=5792`、`compile_ok>=1536`，并抽查“2006年-12年”“最近的第二天”“本月的前一周”“2018年的第五年”等年份区间和复合日期样例不再生成无意义的 `1=1`。
7. 选择至少 10 条 `compiled_samples`，逐条在 Doris 运行 `EXPLAIN` 和 `COUNT(*)`。
8. 对普通过滤、rank、窗口聚合、技术特征表、prefix 特征表分别记录多轮耗时。
9. 生成 `reports/official_doris_evidence.md` 和 JSON sidecar。
10. 将轻量报告导出到 `submission_artifacts/evidence_snapshots/`，再更新 README、提交说明、答辩 PPT 数据页。

## 21.7 当前验收口径

当前可以自信说明：项目已经完成官方真实数据适配的主要编译器工作，能够解析官方 DSL，识别官方三表，映射可支撑指标，生成无伪造字段的 Doris SQL，并对无法落地的样例给出稳定、可解释的缺失数据域分类。

当前不能夸大说明：官方真实 Doris 性能证据还没有最终采集，因此不能把旧的 5M 合成数据 36.24x 加速说成官方数据加速；也不能说 5799 条官方语料全部完成，因为其中大量语料要求财务、基金、指数成分、用户持仓、龙虎榜等本批数据没有给出的数据域。

下一步拿奖的关键不在“再多写几页材料”，而在把官方 CSV 真正放进 Doris，跑出可复现的行数、EXPLAIN、延迟和加速证据。只要这一步闭环，项目的答辩逻辑会非常完整：大模型负责辅助理解和候选 DSL，确定性编译器负责可信转换，Doris 负责真实高性能执行，覆盖率报告负责解释边界，测试和 Git 负责回溯。
