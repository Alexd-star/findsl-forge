# 数据与证据

## 1. 数据分层

项目把数据分为三层，避免把“代码支持”与“本地碰巧有数据”混在一起。

| 层 | 内容 | 用途 |
| --- | --- | --- |
| 官方层 | 证券代码信息、日频基础行情、日频扩展行情 | 评委离线复现和主要评分证据 |
| 确定性派生层 | 前缀表、技术特征、月度/分区汇总、最新快照 | 从官方事实表按固定 SQL 构建的性能路径 |
| 公开扩展层 | 行业、指数成员、概念、证券画像、交易规则和指数行情 | 覆盖官方包未提供但有权威口径的范围语义 |

`official_only` 只允许前两层；`enriched_public` 才允许引用已登记的第三层。编译请求本身不联网，公开数据必须先同步、校验、固化快照并装载 Doris。

## 2. 官方数据如何使用

`deploy/doris/official/01_schema.sql` 建立官方三张基础表；`04_feature_tables.sql`、`05_technical_features_by_market.sql` 和 `06_partitioned_rollup_serving.sql` 构建可再生的特征与汇总表。装载脚本使用文件 SHA-256 生成幂等标签，并要求 strict mode、过滤行数为零、表行数和日期水位符合预期。

当前证据快照中的官方基础数据为：

- `hsj_stock_code_info`：5686 行。
- `hsj_stock_hq_basic`：13,650,347 行，2006-01-04 至 2026-04-14。
- `hsj_stock_hq_ext`：6,170,822 行，2018-08-20 至 2026-04-14。

这些数字是数据快照身份的一部分，不应硬编码为永远不变的业务常量。换数据包后必须重新执行水位检查和全部正确率/性能实验。

## 3. 公开数据准入

`configs/official/external_source_registry.json` 记录来源、授权/使用说明、抓取方式、快照时间、覆盖范围和更新政策。正式目录只有同时满足以下条件才可启用：

1. 来源可以追溯，名称和标识符有确定定义。
2. 成员集合完整，不是搜索结果中的几个示例。
3. 快照日期和有效期明确；历史查询不错误使用当前成员。
4. 原始响应、规范化结果和校验摘要可复现。
5. 与证券主键、交易日和市场代码的连接规则明确。

名称相似不是成员关系。对于“英美贸易业”“深证龙科”等歧义或疑似噪声目标，系统保留结构化拒绝，不做编辑距离猜测。

## 4. 当前缺口

官方 5799 条语料的当前终态分类为：成功 1083、数据不可用 1720、非法输入 2466、能力缺口 530。旧严格成功集还剩 53 条未迁移，涉及 57 个范围目标、76 次出现；审计分类包括歧义非标准名称、派生语义、赛题域外资产、疑似无效名称和需要供应商快照的成员集合。

这些数字解释了“为什么不是 5799 条都生成 SQL”：语料既包含有效查询，也包含错误示例、官方数据包未覆盖的数据域和无法确定业务口径的名称。可靠系统的目标不是盲目提高成功数，而是在能证明含义和数据来源时成功，否则明确拒绝。

当前逐条裁决见：

- `submission_artifacts/evidence_snapshots/current_official_gap_taxonomy.md`
- `submission_artifacts/evidence_snapshots/current_scope_data_gap_audit.md`
- `configs/official/scope_gap_adjudications.json`

## 5. 正确率证据

`data/official_correctness/manifest.jsonl` 定义 eligible 用例，`reference_sql/` 保存独立编写并冻结的期望 SQL。评测在同一 Doris 快照上执行生成 SQL 与 reference SQL，比较完整规范化结果、行数和哈希。

正式清单为 240 条，覆盖全部 12 类函数和主要计划族。它由 127 条历史人工 reference、30 条平衡跨函数组合、82 条关系代数对抗组合和 1 条配置式新函数用例构成。对抗组合覆盖交集、并集、`(A AND B) OR C` 与 `(A OR B) AND C`，空集与非空集都比较完整哈希；`relative_gap` 另以独立 SQL 验证 5573 行结果。最终准确率和 Wilson 95% 区间以 `official_correctness_benchmark.json` 为准，不能外推为所有未知输入必然正确。

## 6. 性能证据

不同实验不得混成一个“系统平均加速”：

| 实验 | 当前结果 | 证明范围 |
| --- | --- | --- |
| 官方长周期五类矩阵 | 最低 `11.28x`，中位 `13.00x` | 五类 5000 交易日 SUM/AVG 工作负载均达到 `>=10x` |
| 官方常规 20 日前缀路径 | `12.107x` | 该窗口工作负载的前缀收益 |
| 500 万行合成扩展性 | `17.775x` | 合成规模下的优化潜力 |
| Phase 6C 投影前缀 | 中位 `1.393x` | 14 条特定投影路径均更快 |
| 正式逐问句矩阵 | `48/48 <10s` | 纳入矩阵的查询，最大 P95 `3735.34ms` |

每份报告都应包含工作负载、数据指纹、预热、重复次数、缓存设置、基线/优化 SQL、结果哈希、P50/P95 和 Git HEAD。

## 7. 证据目录

`reports/` 是本地可再生成工作区，默认忽略；`submission_artifacts/evidence_snapshots/` 只保存当前评分所需快照。当前树不保存 PPT、视频、截图和长篇手册，避免展示材料引用旧数字。

最终封板顺序是：冻结代码和配置，检查 Doris 水位，重跑正确率与性能，生成 readiness，导出精简快照，核对证据合同，提交证据更新，再制作最终展示材料。
