# 开发路线

## 1. 当前判断

主架构方向正确，不需要推倒重来。当前低效感主要来自早期以阶段文件和单句缺口推动开发，造成文档、证据和兼容代码同时增长。后续必须以“通用能力族 + 可量化退出条件”为单位推进，正式编译链保持单一主线，最终展示材料等功能封板后再制作。

## 2. 开发优先级

### P0：评分硬门禁封板

1. **统一编译延迟基准。** 建立覆盖 12 类函数、深嵌套、复合布尔、多阶段排名和多候选计划的冻结语料；预热后重复至少 30 轮，记录 parse/bind/lower/optimize/physical/render/validate 分段 P50/P95/P99。退出条件是代表性全谱 P95 `<50ms`，而不只是简单 readiness 样例。
2. **完成新函数零核心改动盲测。** 由独立测试新增一个此前不存在的标量函数和一个窗口/关系模板；不修改 parser、binder、planner、backend 核心文件，在真实 Doris 上与 reference SQL 完整结果一致。若全新关系语义无法由模板表达，应明确插件边界，不做虚假承诺。
3. **扩充独立正确率。** 从 157 条扩到内部 240 条目标，优先增加跨函数、空值、边界日期、排名并列、大结果集和相互作用用例；每条必须有独立来源与 reference SQL。退出条件是准确率 `>=98%`、Wilson 95% 下界 `>=95%`、12 类函数和主要计划族覆盖。
4. **最终 Doris 重采。** 在冻结数据和配置上重跑 48 条性能矩阵、长周期门禁、常规前缀、复权策略和范围政策；全部结果一致，矩阵 P95 `<10s`，长周期 `>=10x`。
5. **同一证据基线。** readiness、metadata、README 数字和证据合同必须来自同一代码基线和同一数据快照。展示材料尚未制作，因此只需先封住机器证据。

### P1：完整性与泛化

1. 为 12 类函数建立“Grammar -> Typed AST -> Logical IR -> Physical IR -> SQL -> reference case”逐项追踪矩阵，并由测试自动校验覆盖。
2. 对剩余 530 条能力缺口按日期代数、时序事件、排名组合、约束和数据域分簇；只开发能覆盖一类语句的通用节点或规则。
3. 对 53 条迁移数据缺口执行准入裁决：有完整权威成员关系的接入版本化数据；可由现有事实表确定推导的实现派生规则；歧义、噪声和赛题域外项保持拒绝。
4. 完成 Web/API 的评委主流程复核：正例、负例、诊断、SQL、IR、证据状态和 Doris 健康；检查窄屏、加载、空状态和服务失败状态。
5. 删除不再被调用的兼容模块前，先采集调用关系和差分覆盖；连续稳定后按包删除，不做一次性大拆除。

### P2：非竞赛阻塞的产品化增强

- API 鉴权、配额、审计日志和敏感配置生命周期。
- 多实例并发、背压、资源限额和超时策略。
- 指标、日志、追踪、告警及运行手册。
- Doris 多节点高可用、备份恢复、滚动升级和灾难演练。

这些项目有助于生产部署，但不应挤占赛题 P0/P1 的正确率、扩展性和真实性能封板。

## 3. 每个能力族的标准流程

1. 从全量语料生成最小失败簇，记录统一错误码和共同语义。
2. 判断应修改 Grammar、Typed AST、Binder、Logical IR、Rule、Physical Strategy、Backend 还是数据目录。
3. 先写一个最小正例、一个负例、一个边界例和一个跨能力组合例。
4. 在正确层实现通用节点或规则，禁止匹配 Excel 行号、完整 DSL 或单个证券名称。
5. 跑局部测试、全量测试、官方漏斗差分和架构边界。
6. 在 Doris 上与独立 reference SQL 比较完整结果，并采集 P95/EXPLAIN/Profile。
7. 只有受影响语料均闭环且未制造新退化时，才更新当前证据。

## 4. 停止条件

竞赛开发可以进入最终材料阶段，需要同时满足：

- 全部官方功能要求有代码、测试和可复核路径；不能实现的输入有合理且稳定的边界说明。
- 正确率、长周期加速、编译延迟和查询延迟均由冻结基准证明达标。
- 新指标与新函数扩展完成独立盲测。
- 关键证据无 warning，Git、数据和配置身份一致。
- README、五份技术文档、机器证据和实际命令不存在旧数字或断链。
- 工作树干净，CI 通过，远端 main 指向经过验证的提交。

满足这些条件后，再一次性制作操作手册、PPT、图表、截图和视频。最终材料只引用封板证据，不再反向推动核心开发。
