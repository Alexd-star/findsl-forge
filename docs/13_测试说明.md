# 13 测试说明

本文档说明项目测试体系和运行方式。

## 1. 测试目标

测试不仅验证函数是否返回预期值，还要证明 DSL 语义、Doris SQL、reference oracle、Doris 资产、LLM 安全边界和提交证据链一致。

## 2. 全量测试

```powershell
python -m pytest -q
```

当前测试数量以实际输出为准。最近证据快照中显示全量测试通过，详见 `submission_artifacts/evidence_snapshots/submission_readiness.md`。

## 3. 重点测试文件

| 文件 | 重点 |
|---|---|
| `tests/test_parser.py` | DSL 语法解析。 |
| `tests/test_semantic.py` | 函数参数、类型、窗口、rank 和错误拦截。 |
| `tests/test_compiler.py` | SQL 片段、trace 和 explain。 |
| `tests/test_equivalence.py` | SQL/reference 行集一致性。 |
| `tests/test_doris.py` | Doris DDL 和 prefix SQL。 |
| `tests/test_doris_sql.py` | SQL validator。 |
| `tests/test_nl2dsl.py` | 中文模板覆盖。 |
| `tests/test_llm_adapter.py` | LLM 候选安全验证。 |
| `tests/test_readiness.py` | 提交门禁。 |

## 4. 推荐测试顺序

开发小改动：

```powershell
python -m pytest tests\test_compiler.py tests\test_equivalence.py -q
```

提交前：

```powershell
python -m pytest -q
powershell -ExecutionPolicy Bypass -File .\scripts\submission_readiness.ps1
```

## 5. 测试数据

测试默认使用 `data/samples/`。真实行情测试使用 `data/real_samples/eastmoney_a_share_sample/`。合成规模数据可由脚本生成，不建议提交。

## 6. 新增测试建议

1. 新增 SQL 算子时必须补 reference 等价测试。
2. 修改 NULL 语义时必须构造稀疏辅助表样本。
3. 修改 Doris 资产时必须补 `test_doris.py`。
4. 修改 readiness 时必须补 `test_readiness.py`。
