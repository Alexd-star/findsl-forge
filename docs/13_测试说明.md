# 13 测试说明

本文档说明项目测试体系和运行方式。

## 1. 测试目标

测试不仅验证函数是否返回预期值，还要证明 ANTLR、Typed AST、领域绑定、Logical/Physical IR、Doris SQL、独立 oracle、Doris 资产、AI 安全边界和提交证据链一致。迁移率、解析率和 pytest 通过数不等于正式 SQL 正确率。

## 2. 全量测试

```powershell
python -m pytest -q
```

当前工作区为 `1042 passed`；已导出的正式快照仍为 `1040 passed`。最终提交应在 clean HEAD 重新生成 readiness 和 metadata 后统一数字。

## 4. 推荐测试顺序

开发小改动：

```powershell
python -m pytest tests\official\test_pipeline.py tests\test_official_gap_analysis.py -q
```

提交前：

```powershell
python scripts/generate_antlr.py --check
python -m ruff check .
lint-imports
python -m pytest -q
powershell -ExecutionPolicy Bypass -File .\scripts\submission_readiness.ps1
```

## 5. 测试数据

测试默认使用 `data/samples/`。真实行情测试使用 `data/real_samples/eastmoney_a_share_sample/`。合成规模数据可由脚本生成，不建议提交。

## 6. 新增测试建议

1. 新增 SQL 算子时必须补 reference 等价测试。
2. 修改 NULL 语义时必须构造稀疏辅助表样本。
3. 修改 Doris 资产时必须补 `test_doris.py`。
4. 修改 readiness 时必须补 `test_readiness.py`。
5. 修改提交证据导出、答辩指标或 Doris evidence JSON 字段时，必须补 `test_evidence_metadata.py`，确认 `submission_artifacts/evidence_metadata.json` 仍能正确抽取关键数字。
6. 修改正式官方模块依赖时必须运行 import-linter，禁止核心重新导入旧管道。
7. 新增官方能力应按能力簇回归全部匹配语料，不只验证触发开发的单条 DSL。
