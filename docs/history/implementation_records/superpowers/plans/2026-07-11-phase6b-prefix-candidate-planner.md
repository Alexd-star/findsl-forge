# Phase 6B 前缀多候选物理规划实施计划

## 目标

让一个逻辑指标拥有多个受控物理实现，并由 Phase 6A 的真实统计成本选择执行路径。首批覆盖固定日均线与日均量线：技术特征表直接列作为热点物化候选，基础前缀表差分作为通用前缀候选。

## 真实数据依据

- `hsj_stock_hq_basic_technical` 与基础行情均为 `13,650,347` 行，保存固定 MA 与均量列。
- `hsj_stock_hq_basic_prefix` 同为 `13,650,347` 行，包含 `row_no`、`close_prefix`、`close_count_prefix`、`volume_prefix` 和 `volume_count_prefix`。
- N 日平均值严格使用当前累计值减去 `row_no-N` 累计值，再除以有效计数；价格结果除以 `10000.0`。
- 前缀表不保存原始当日成交量或当日资金流，因此不能替代普通 `indicator(成交量)` 或 `indicator(主力净流入)`。

## 架构

新增独立、Schema 校验的 `physical_strategies.json`。物理目录继续保存直接字段，策略注册表只保存受控派生参数，不保存 SQL 字符串。规划器为单指标表达式枚举：

1. `direct_column`：现有技术表物化列；
2. `prefix_average`：基础行情稳定骨架 + 前缀表当前/历史累计差分。

候选成本：

- 直接列：技术表 + 基础锚表扫描字节；
- 前缀平均：基础骨架 + 两次前缀资源访问的保守字节上界。

成本只负责确定候选顺序。候选要成为可用实现，还必须通过 Physical IR 验证、SQLGlot Doris AST、安全 lint、真实 Doris 行数与 SHA-256 等价。若实测性能与静态成本冲突，记录校准因子，不篡改结果正确性门禁。

## TDD 顺序

1. 策略注册表：严格字段、指标/资源引用、窗口和列名校验。
2. 多候选枚举：直接与前缀候选均进入决策轨迹，成本稳定排序，拒绝原因完整。
3. `PhysicalPrefixAverage` 表达式：类型、资源、窗口与比例验证。
4. SQLGlot 后端：只使用 AST 节点生成相关前缀差分子查询，不接受 SQL 片段。
5. 真实 Doris：固定均线/均量代表样本的新旧行集哈希一致，保存 EXPLAIN 与重复耗时。
6. 全量回归、中文文档、证据归档和 Git 推送。

## 明确不做

- 不把 `volume_prefix` 当成当日成交量。
- 不把 `main_net_tur_prefix` 当成当日主力净流入。
- 不为动态窗口或多指标混合表达式静默选择不完整候选。
- 不以静态字节成本替代真实 Doris 性能证据。
