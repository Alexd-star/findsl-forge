# Phase 6C 集合式前缀 CTE/Join 计划

## 1. 问题定位

Phase 6B 为固定均线和均量线建立了前缀差分候选，但后端把每个 `PhysicalPrefixAverage` 渲染为相关标量子查询。对基础行情的每一行，数据库都需要重新关联当前前缀行和窗口前一行。旧实测中，5 日均线和 5 日均量线的前缀路径分别只有技术表路径的 `0.795x` 和 `0.734x`，因此只能保留为 shadow。

Phase 27 已将无日期直接指标下推到最新交易日快照，为集合化创造了条件。本阶段目标是将前缀值提升为命名关系，一次性按 `(mktcode,tgtcode,bizdate)` 连接当前前缀行，再按 `(mktcode,tgtcode,row_no-window)` 左连接历史累计行，消除逐行相关子查询。

## 2. 类型化关系合同

新增 `PhysicalPrefixRef` 和 `PhysicalPrefixJoin`。前者引用命名前缀投影，后者显式保存锚点输入、一个或多个受控 `PhysicalPrefixAverage` 投影以及可选布尔谓词。`join_semantics=stable_observation` 声明输出粒度仍是证券交易日，不允许缺少稳定键或自由 SQL 片段。

验证器要求投影别名唯一、投影表达式必须是目录可验证的前缀平均、谓词只能引用已声明投影。筛选计划在 `PhysicalPrefixJoin` 内应用谓词；排名计划可只投影前缀值，再由上层 `PhysicalRank` 使用同一命名列。

## 3. Doris SQL 结构

SQLGlot 后端生成两级 CTE：

1. `prefix_anchor_rows`：先执行市场、日期和最新快照裁剪；
2. `prefix_values`：锚点行与当前前缀行 Inner Join，再与窗口前累计行 Left Join，投影差分平均值。

最终筛选或排名只引用 `prefix_values.prefix_value`。生成 SQL 不再包含 `WHERE (SELECT ...)` 相关标量结构。价格均线继续除以 `10000.0`；有效值数量使用独立 count 前缀差分并以 `NULLIF` 防止除零。

## 4. 成本与计划形态校准

14 个固定均线/均量策略经真实 Doris 筛选矩阵验证后由 `shadow` 调整为 `active`。成本模型仍使用基础扫描与两次前缀资源访问的保守字节上界；实测证据另外保存 EXPLAIN 扫描节点、投影列、分区、基数和基于字段逻辑宽度的投影成本。该成本明确标注为模型值，不冒充实际存储读取字节。

策略激活按算子形态执行。筛选计划 14/14 均获得稳定提升，因此默认使用集合式前缀 Join。排名热缓存基准与技术列基本持平，价格排名存在约 3% 波动性回退，所以排名默认继续使用技术特征列；前缀排名保留为显式 shadow 候选并具备完整关系实现。这样避免用平均收益掩盖具体计划回退。

## 5. 真实 Doris 结果

`scripts/collect_phase6c_set_prefix_evidence.py` 对全部 14 个策略执行 1 次预热、5 次正式重复，并比较技术列和集合前缀路径的完整结果集 SHA-256。首轮实现绑定结果为：

- 完整行集哈希一致：`14/14`；
- CTE/Join 结构合同：`14/14`；
- 集合前缀路径更快：`14/14`；
- 中位加速比：约 `1.55x`；
- 最低加速比：约 `1.23x`；
- 最高加速比：约 `2.00x`。

全部结果均来自 13,650,347 行官方 Doris 行情、技术表和前缀表。正式交付证据以提交后重新生成的 `submission_artifacts/evidence_snapshots/phase6c_set_prefix_doris.*` 为准。

## 6. 回归边界

官方迁移覆盖保持 `690/1097（62.90%）`，没有因策略切换增加或减少可编译问句。前缀路径只用于目录声明的固定价格均线和均量线，不把累计成交量当作当日成交量，也不扩展到缺失数据域。若 Doris 表布局、统计快照或数据规模变化，应重新运行 14 策略矩阵；未通过哈希和性能门禁时可通过配置和无策略基线回退到技术列。
