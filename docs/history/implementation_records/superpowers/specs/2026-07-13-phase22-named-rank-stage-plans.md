# Phase 22：命名排名表达式与候选集阶段计划

## 1. 阶段目标

Phase 22 解决排名算术、过滤后排名、聚合后排名、链式排名和括号阶段分支。核心约束不是“让更多 SQL 能执行”，而是保持编译器关系语义：每次排名必须有明确总体，每个 `then` 必须消费前一阶段的候选证券集合，百分位分母必须来自当前阶段，非单日指标不得让同一证券重复参与排名。

所有新增路径继续经过 ANTLR、Typed AST、Logical IR、Physical IR、SQLGlot Doris AST 和后端验证。旧后端 SQL 不进入新计划；缺失数据域、无法界定的作用域和未实现事件组合仍返回结构化错误。

## 2. 命名排名表达式

`PhysicalNamedRank` 表示一个独立排名关系，包含输入关系、指标表达式、方向、聚合函数和输出别名。`PhysicalRankExpression` 保存若干命名排名关系以及最终布尔或算术谓词。后端分别物化各排名，再按 `(mktcode,tgtcode)` 与锚点关系连接；除法分母使用 `NULLIF(rank_value,0)`。

这种设计适用于排名相加、相减、相除以及不同日期排名的比较。每个排名调用保留自己的市场、日期、指标和聚合合同，不会把两个日期范围合并成互相矛盾的行谓词。精确日期直接排名；区间日期且未声明聚合函数时，先通过 `MAX_BY(value,bizdate)` 取得区间末值，使每只证券只进入一次横截面总体。

## 3. 候选集阶段排名

`PhysicalStageRank` 的输入是完整的前序 Physical Plan，而不是前序谓词的局部字段。规划器递归调用 `plan_physical` 物化前序过滤、聚合、时序或排名计划，再把输出按证券稳定键去重。排名指标从独立度量关系取得，并只与前序候选集连接。

链式排名因此形成严格的数据流：

```text
原始关系 -> 阶段一候选集 -> 阶段一横截面排名
         -> 阶段二候选集 -> 阶段二横截面排名
```

百分位阶段使用 `COUNT(*) OVER()` 计算当前候选集规模，不能复用全市场或其他时间桶的计数。排序以指标为主键，并以 `mktcode,tgtcode` 作为确定性并列次序。聚合阶段指标先按证券执行 `SUM/AVG/MIN/MAX/GROWTH_RISE/GROWTH_FALL`，再进入排名。

## 4. 括号阶段分支与时序区间排名

Lowering 层先在括号内部展开 `then`，再构造外层 `and/or`。因此 `(filter then rank) or (filter then rank)` 会成为两个 `LogicalStage` 分支上的集合并集，不会把 `then` 泄漏成 SQL 运算符。

`PhysicalTemporalRank` 增加上下界及开闭区间合同。`between '[5%,10%]'` 在每个时间桶只计算一次共同排名总体，分别生成下界和上界：

```text
rank >= CEIL(population * 5 / 100)
AND rank <= CEIL(population * 10 / 100)
```

之后再按证券执行 `CONS/EXIST`。上下界单位必须同为普通数值或同为百分比，百分比不得超过 100。

## 5. 规划与后端不变量

1. `PhysicalRankExpression.input`、每个命名排名输入、`PhysicalStageRank.input` 和度量输入均递归通过 Physical IR 校验。
2. 排名关系不能为空，别名不得重复，最终谓词只能引用已声明的排名输出。
3. 阶段排名界值必须是非负数；百分比上限为 100。
4. 生成 SQL 不包含 `1=0`、`1=1`、任意 SQL 字符串逃生口或被忽略的槽位。
5. 候选集连接使用证券稳定键；日期用于确定输出快照或区间度量，不被误作跨期证券身份。
6. 区间内非聚合度量必须折叠为每证券一行，防止 Join 放大和重复排名。

## 6. 官方工作簿结果

Phase 21 基线为 `631/1097`。Phase 22 在同一份 5,799 行官方工作簿上达到 `647/1097（58.98%）`，新后端总成功数为 663，净增加 16 条。新增策略分布为：`stage_rank` 7 条、`named_rank_expression` 5 条、`set_union` 2 条、`temporal_rank` 1 条和 `limit_stage_rank` 1 条。

`scripts/audit_phase21_new_successes.py` 以 Phase 21 快照为基线重新编译 16 条新增成功，逐条检查后端验证、占位谓词、聚合、时序和窗口排名是否真实物化，结果为 `16/16 PASS`。漏斗中原有排名表达式与链式排名错误类别已清零。

## 7. 真实 Doris 结果

`scripts/collect_phase22_stage_rank_evidence.py` 在 13,650,347 行官方行情表上执行七组生成 SQL，并与独立编写的集合式参考 SQL 比较完整三列结果集。用例覆盖即时排名算术、区间末值排名算术、链式候选排名、聚合过滤后排名、时序过滤后周期排名、括号阶段并集和百分位区间连续排名。

七组结果均为非空，完整结果集 SHA-256 一致 `7/7`。单次预检中的最大 P95 低于 0.55 秒；最终版本化报告会在提交代码后重新采集两次执行数据，并保存每条生成 SQL、参考 SQL、差异样本和 EXPLAIN 摘要。

## 8. 当前边界与下一阶段

剩余 450 条旧严格成功集迁移缺口中，294 条明确涉及当前官方资料未提供的证券范围、行业成员或其他数据域。代码侧下一批高价值问题包括 10 条 Logical Lowering、7 条多谓词时序关系、7 条标量作用域无界、6 条事件组合以及少量日期与事件周期合同。

下一阶段应优先实现“多谓词时序关系 + 事件组合”的统一关系计划，而不是为缺失数据字段生成猜测 SQL。对缺失数据域，完成标准是稳定错误码、字段需求和可接入资源合同，不是虚假的 backend success。
