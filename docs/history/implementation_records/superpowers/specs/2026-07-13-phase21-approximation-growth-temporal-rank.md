# Phase 21：配置化近似、增长聚合与时序排名

## 1. 阶段目标

Phase 21 合并处理旧严格成功集中的近似比较、增长函数、聚合加 `CONS/EXIST`、增长排名和时序排名缺口。实现继续遵守新编译器的边界：语义必须进入 Typed Physical IR，SQL 必须由 SQLGlot AST 生成；不复用旧后端 SQL 字符串，不忽略 `agg_func`、`count_exp`、日期、市场或排名方向，也不以 SQL 可解析代替结果正确。

## 2. 配置化近似策略

`configs/official/approximation_policy.json` 将数值近似比较定义为 1% 相对容差和 0.01 绝对下限。数值 `left ~= right` 被物理化为：

```text
ABS(left - right)
<= GREATEST(0.01, 0.01 * GREATEST(ABS(left), ABS(right)))
```

该规则同时覆盖普通标量、跨资源表达式、命名标量子查询和窗口事件投影。非数值近似比较继续返回结构化错误，不退化成精确相等。真实 Doris 用例“最新价约等于 10”返回 38 行，与独立参考 SQL 的完整结果集哈希一致。

## 3. 增长函数

`GROWTH_RISE` 和 `GROWTH_FALL` 成为正式集合聚合函数。周期首值和末值分别使用 Doris `MIN_BY(value,bizdate)` 与 `MAX_BY(value,bizdate)` 取得，公式为：

```text
rise = (last - first) * 100 / NULLIF(ABS(first), 0)
fall = (first - last) * 100 / NULLIF(ABS(first), 0)
```

SQLGlot 表达式树对差值添加显式 `Paren`。首轮端到端审计曾发现未加括号时 SQL 会被输出成 `last - first * 100 / denominator`；该优先级错误已经修复并加入回归测试。零基数返回 `NULL`，不会被改造成零或真值。

## 4. 聚合时序关系

新增 `PhysicalTemporalAggregate`，明确表达“窗口取数、按桶聚合、指标比较、时序量化、回到最新快照”五个阶段。普通 `SUM/AVG/MAX/MIN` 按日、周、月、季度或年分桶；日粒度增长先按证券和交易日形成日值，再在独立 CTE 中只计算一次 `LAG`，用相邻交易日变化率判断。周、月、季度和年粒度增长使用桶内首尾值。

`EXIST` 统计满足指标条件的桶数；`CONS` 使用全序号减命中序号的 gaps-and-islands 方法求最长连续段；“每日/每月”等 every 合同要求非空且命中桶数等于总桶数。日序列按真实交易日排列，周期序列使用连续的年、月、季度或周序号，避免把跨缺口月份误判为连续。

## 5. 时序排名关系

新增 `PhysicalTemporalRank`，执行顺序固定为：

1. 根据日期合同裁剪交易窗口；
2. 需要 `agg_func` 时先按证券和时间桶计算聚合值；
3. 在同一交易日或同一周期桶内按指标值做横截面 `ROW_NUMBER`；
4. 百分位排名使用桶内 `COUNT(*)` 和 `CEIL(population * percent / 100)`；
5. 对每只证券的排名命中结果执行 `CONS/EXIST`；
6. 将合格证券连接回最新行情快照。

该节点修复了开发中发现的一次假阳性：早期草案曾把 `rank(...,GROWTH_RISE,CONS=...)` 当成普通聚合时序，遗漏横截面排名。现在 rank 调用不会进入 `PhysicalTemporalAggregate`，只能由包含真实窗口排名的 `PhysicalTemporalRank` 接收。

## 6. 官方漏斗与审计

Phase 20 稳定基线为 `534/1097`。本阶段官方 5,799 条工作簿漏斗达到 `631/1097（57.52%）`，新后端总成功数为 647。相对 Phase 20 新增成功 99 条，策略分布包括集合交集 29 条、稳定键 Join 18 条、受控表达式 13 条、时序排名 10 条、复合聚合 9 条、聚合排名 7 条、聚合时序 6 条以及其他已验证路径。

`scripts/audit_phase21_new_successes.py` 对 99 条新增成功逐条重新编译，检查后端验证、占位谓词、近似容差、聚合函数、时序关系和排名窗口是否真实存在，结果为 `99/99 PASS`。该审计证明相关槽位没有被静默丢弃，但不替代真实数据库结果比对。

## 7. 真实 Doris 结果

`scripts/collect_phase21_aggregate_rank_evidence.py` 在 13,650,347 行真实 Doris 行情表上执行六类生成 SQL，并使用独立编写的参考 SQL比较完整结果集。六类包括配置化近似、五交易日增长、逐日增长 `EXIST`、日聚合连续段、增长 Top 10 和逐日增长百分位时序排名。结果为 `6/6` 完整结果集 SHA-256 一致，且 `6/6` 均为非空结果；每条保存生成 SQL、参考 SQL、执行时间和 EXPLAIN 摘要。

## 8. 当前边界

剩余迁移缺口以官方数据缺失为主：257 条证券范围数据缺失、106 条领域能力缺失、22 条数据域缺失和 15 条行业成员数据缺失。代码侧剩余高价值项包括 11 条排名算术或阶段组合、5 条链式排名、7 条多谓词时序关系和少量事件与时序组合。它们需要命名阶段输出或多分支关系计划，不能用当前节点强行接收。

本阶段没有把 `631/1097` 表述为总语料正确率。迁移分母是旧严格后端的 1,097 条成功集；缺数据问句继续返回可审计诊断。后续应优先实现阶段化 Rank IR 和多谓词时序分支，再讨论缺失数据域的外部接入合同。
