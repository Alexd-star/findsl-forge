# Phase 23：复合时序关系、跨资源窗口与排名区间

## 1. 阶段目标

Phase 23 处理三类具有共同关系语义的缺口：同一 `CONS/EXIST` 量词下的多指标逐桶谓词、跨基础行情与技术指标资源的时序比较，以及普通/聚合/阶段排名的区间约束。实现目标不是扩大 SQL 接受面，而是让量词、排名总体、阶段候选集和稳定键 Join 在 IR 中都有不可绕过的结构化合同。

## 2. 对齐的复合时序谓词

同一个比较表达式可以包含多个都填写了 `count_exp` 的函数。只有以下属性全部一致时，Lowering 才把它们合并为一个 `LogicalConsecutive` 或 `LogicalExist`：

1. `CONS/EXIST` 模式；
2. 比较符、阈值、上限、时间单位与“每周期”标记；
3. 交易序列语义；
4. 市场集合、日期窗口、证券范围和选择类型。

合并后，所有指标先在同一证券、同一交易桶中组成布尔谓词，再统计命中桶或最长连续段。例如“成交量/成交额连续三日大于零”只生成一套 source、eligible、hits、runs 和 qualified CTE。若一个调用为 `CONS=3日`、另一个为 `EXIST=3日`，或日期/市场不同，编译器继续返回稳定错误，不能任意选取其中一个量词。

`CONS!=每日` 的含义也得到完整保留：窗口必须非空，且命中桶数不等于总桶数。后端原有的不等式集合语义已经存在，本阶段修复的是 Logical IR 对该官方合法合同的误拒绝。

## 3. 跨资源时序 Join

`PhysicalTemporal.input` 由“只能是直接扫描”升级为“可渲染的同实体物理关系”。规划器复用目录中的稳定键交集构造左深 Join；基础行情和技术特征都带日期时，连接键固定为 `(mktcode,tgtcode,bizdate)`。窗口排序与日期裁剪使用关系根节点的分区键，指标列则通过资源别名读取。

该设计避免两个常见错误：只按证券代码连接造成跨日期笛卡尔积，以及分别计算两条时序结果后再比较无法对齐交易桶。Physical IR 校验会递归检查 Join 两侧、逻辑实体和每一个目录声明的稳定键。

## 4. 排名区间合同

`LogicalRank`、`PhysicalRank`、`PhysicalAggregateRank` 和 `PhysicalStageRank` 均增加上界及上下界开闭标记。`between '[5%,10%]'` 在一个排名总体中生成：

```text
rank >= CEIL(population * 5 / 100)
AND rank <= CEIL(population * 10 / 100)
```

上下界必须同为普通数值或同为百分比，上界不能小于下界，百分比不能超过 100。普通排名、先聚合后排名和 `then rank` 共用同一边界校验与 SQLGlot 比较构造逻辑；不存在只在某一个入口支持区间的旁路实现。

## 5. 关系树字段发现

原字段收集器按 Filter/Rank/Stage 的单链向下遍历，当前序候选集是 `LogicalSetOperation` 时会在规划前错误终止。Phase 23 将其改为递归关系树遍历：集合分支分别检查，Stage 遍历其完整 operation，最终叶子必须仍为 `LogicalDomainScan`。

因此，“排名与标量过滤取交集，再对交集做第二次排名”会先生成 PhysicalSetOperation，然后由 PhysicalStageRank 把该集合物化为候选总体。字段收集、Physical IR 校验和后端 CTE 嵌套都保持同一棵关系树，不复制或丢弃前序谓词。

## 6. 官方工作簿结果

Phase 22 基线为 `647/1097`。本阶段达到 `660/1097（60.16%）`，新后端总成功数为 677。迁移分母内净增加 13 条；全部工作簿中共有 14 条由失败变为 backend success，其中一条不属于旧严格成功集。

新增成功集策略包括普通时序、稳定键跨资源时序 Join、集合交集和阶段排名。逐条审计结果为 `14/14 PASS`，检查内容包括后端 AST 验证、占位谓词、量词物化、窗口排名、上下界以及阶段候选关系。

## 7. 真实 Doris 结果

`scripts/collect_phase23_relational_evidence.py` 在 13,650,347 行基础行情表及对应技术特征表上执行六组生成 SQL，并与独立参考 SQL 比较完整结果集。用例覆盖“非每日”、同表复合时序算术、跨表时序 Join、直接百分位排名区间、候选集排名区间和集合候选后再次排名。

预采集结果为 `6/6` 完整 SHA-256 一致且 `6/6` 非空；跨表时序用例返回 2929 行，生成 SQL与独立稳定键 Join/连续段参考返回完全一致。最终证据在实现提交后重新采集两次执行时间并版本化。

## 8. 当前边界

剩余高价值代码缺口集中在七条非单日标量与聚合混合、六条事件与聚合/时序组合、五条特殊日期表达和少量带负数 count 的 limit 语义。下一阶段应优先抽象“命名周期末标量关系”，复用 `MAX_BY(value,bizdate)` 和稳定键 Join；事件组合需要先明确跨日期候选集的输出日期合同，不能直接用三列 `INTERSECT` 猜测业务语义。

缺失证券范围、行业成员和数据域仍占迁移缺口主体，继续输出结构化诊断，不计入可执行 SQL 成功。
