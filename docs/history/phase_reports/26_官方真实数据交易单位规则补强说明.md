# 官方真实数据交易单位与交易制度规则补强说明

## 1. 问题来源

官方真实 DSL 中多次出现“多少手”的表达，槽位通常写成：

```text
indicator(..., '成交量', ...) / indicator(..., '每手股数', ...) > 某个数
```

当前官方三张 CSV 表没有 `每手股数` 字段，因此项目此前把它归入未支持指标。重新核查后可以看到，这类表达大多用于 A 股股票行情语境，底层 `volume`、`innerVol`、`outerVol` 等字段提供的是股数级或成交量级数值，用户用“手”表达时需要一个交易单位换算。

## 2. 补强原则

本轮不新增外部数据，也不伪造每只股票的特殊属性。只引入一个明确的规则常量：在官方 A 股股票行情数据适配器中，`每手股数` 编译为 `100`。这个常量用于股票语境下的“股数/手数”换算。

如果 DSL 明确指定非股票标的，例如期货、债券、基金、REITs，项目原有 `select_type` 约束会继续生成 `1=0` 并给出 warning，因为官方数据包没有这些标的的真实交易单位和行情表。本轮补强不会把期货合约乘数、债券每手张数、基金份额规则混同为 A 股股票规则。

## 3. 实现方式

在 `INDICATORS` 中加入：

```python
"每手股数": IndicatorMeta("hsj_stock_hq_basic", kind="numeric", expression="100")
```

这样它会像普通数值指标一样进入表达式、rank、聚合和出现次数路径，但本质上是官方 A 股股票适配器的规则常量，不是 CSV 字段。

## 4. 验收方式

新增测试覆盖成交量除以每手股数：

```text
indicator('', '', '成交量', '今天', '', '', '') / indicator('', '', '每手股数', '今天', '', '', '') > 1000
```

期望 SQL 中出现 `base.volume / 100`，并且日期约束仍然正常保留。刷新官方覆盖率后，`UNSUPPORTED_OFFICIAL_INDICATOR: 每手股数` 应明显下降或从 TopN 中消失；如果某条样例同时涉及期货、基金、复牌日期、个人持有比例等缺字段内容，它仍可能继续失败。

## 5. T+0 规则边界

官方样例中还出现了 `是否T+0`。这里同样不能把所有标的混在一起处理。对本项目当前的官方三表来说，真实可查询的数据是 A 股股票行情；在股票适配器下，`是否T+0` 编译为恒假布尔条件 `FALSE`，用于表达 A 股股票不能当天买当天卖。

如果 DSL 明确指定 `ETF`、`LOF`、`场内基金` 等标的，原有 `select_type` 逻辑仍会生成不可落地约束和 warning。原因是官方 CSV 没有基金产品表、基金交易制度字段和跟踪指数信息，不能因为部分 ETF 可能支持 T+0 就在股票行情表上伪造结果。
