# Phase 44 组合范围与中证官方成员修复

## 1. 本阶段为何继续开发

Phase 43 之后，剩余范围中仍有两类可以严格推导，而不必依赖模糊名称匹配。一类是由多个标准范围组合而成的自然语言，例如“宁夏算力概念”和“银行保险”；另一类是明确的六位证券代码或指数收益变体。过去的人工别名只能把一个词指向一个来源范围，无法表达交集、并集和成员数量门禁。若直接维护结果证券名单，代码虽然能通过样例，却无法说明名单从何而来，也无法随来源快照更新。

本阶段把这些需求落为目录层的通用能力。组合范围仍然只是 Physical IR 可消费的成员关系，ANTLR、Typed AST、Logical IR 和 Doris 后端不需要增加题目专用分支。官方工作簿严格迁移由 `990/1097` 增至 `998/1097`，总后端成功数由 1,021 增至 1,029。剩余 99 条严格缺口由 96 条范围成员缺失和 3 条非单值 `queryData` 组成。

## 2. 组合范围的数据模型

审核配置现在支持 `intersection` 和 `union`。每个分量必须提供 `source_snapshot_id` 与 `scope_code`，构建器从 SQLite 版本目录读取成员，以 `(mktcode,tgtcode)` 为稳定键完成集合运算。生成范围的代码由别名、运算类型和分量清单计算 SHA-256 后截取得到，形式为 `CURATED:<fingerprint>`；同一输入总能得到同一代码，任一来源或运算变化都会留下新的指纹。

“宁夏算力概念”使用百度完整地域快照中的 16 只宁夏证券，与东方财富完整板块快照中的 205 只算力证券求交，得到 1 只证券。“银行保险”把 42 只银行证券和 5 只保险证券求并，得到 47 只证券。审计报告保留分量成员数和最终成员数，Doris 只读取生成后的版本化关系，不在 SQL 中展开常量名单。

这一设计遵循关系优化器的基本原则：逻辑集合运算先形成确定关系，再由物理后端选择连接和过滤实现。Apache Calcite 将 `Union`、`Intersect`、`Join` 等作为核心关系算子，并强调规则变换必须保持语义等价；项目的组合范围因此位于目录和关系计划边界，而不是前端字符串替换层。[Apache Calcite Algebra](https://calcite.apache.org/docs/algebra.html)

## 3. 六位证券代码解析

证券范围目录过去支持精确名称和“名称(代码)”两种写法，却拒绝单独六位代码。官方工作簿中的 `queryData('', '300084', ...)` 明显把代码当作基准证券，因此现在允许纯六位数字进入官方证券主表反查。只有代码恰好命中一个证券时才返回结果，并把它标记为显式代码范围；`100429`、`994338` 等不在官方主表中的数字仍返回 `KeyError`，不会被当成自定义板块或虚构证券。

这项能力目前没有单独关闭一条严格迁移缺口，因为包含 `300084` 的问句还同时依赖未解析的“港湾经济”。它仍然提高了泛化能力，也把剩余失败精确收敛到真正缺失的另一个范围。

## 4. 中证成分文件根因修复

复核“沪深300港元净收益指数”时，目录显示早期 `csindex` 快照只有 1 条沪深300成员，而同名指数应有 300 只样本。直接访问中证指数当前 `000300cons.xls` 与 `000300closeweight.xls` 后确认，两份文件均为 300 行；问题来自文件表头已由旧版“成分券代码、成分券名称、日期、权重”改为“成份券代码Constituent Code、成份券名称Constituent Name、日期Date、权重(%)weight”。旧解析器读取不到新列，历史快照没有通过成员数量门禁。

解析器现同时兼容两代表头，并正确处理 Excel 中以整数保存的证券代码和 `YYYYMMDD` 数字日期。同步脚本要求实际成员数与 `--expected-count` 完全一致后才导入。首次重建得到 299 行时，进一步发现官方样本包含证券 `302132`。项目原市场识别只覆盖深市 `300/301` 前缀；根据深交所公告和官方证券主表，该代码为中航成飞在深交所创业板使用的新代码，因此市场规则补入 `302xxx -> mktcode 0`。第二次同步得到严格 `300/300`，快照为 `csindex-2026-07-30-b68b771e8882`。

“沪深300港元净收益指数”仅复用沪深300的样本成员，因为收益口径和计价币种不会改变样本证券；配置明确声明该映射只提供成员范围，不提供或伪造指数自身行情。构建器还要求该来源至少 300 个成员，异常小快照会立即失败。

## 5. Doris 证据

Phase 44 新增 8 条后端成功问句，覆盖指数范围补集、组合并集空指标排名、地域与概念交集的多阶段排名、组合行业时序量化、互联网行业聚合排名和家用轻工事件查询。8 条 SQL 在真实 Doris 上各执行三次，完整结果哈希全部稳定，`8/8 PASS`；4 条为非空结果，最高 P95 为 `780.087 ms`，低于 10 秒门槛。

在最终官方 300 行快照与重新生成的审核别名装入后，外部目录行数必须再次以 Stream Load 清单为准。任何表实际行数不等于导出清单、任何过滤行不为 0，或任一差量 SQL 的三轮哈希不一致，都阻止证据刷新。

## 6. 当前边界

组合能力不意味着可以自动拆解所有长词。“宁夏算力概念”具有清晰的地域与主题交集，“银行保险”具有清晰的行业并集；“科技电池”“深海经济”“S板”等词没有同样唯一的集合表达，仍保留结构化失败。当前 91 个真实未解析范围原子应继续按来源和语义逐项确认，不能使用字符串相似度批量上线。

三条无聚合 `queryData('', '大盘', ...)` 仍然拒绝。当前“大盘”是 199 只大盘股的集合，不是单一指数行情；在赛题方没有给出默认聚合函数前，任取一只证券、任取最大值或隐式平均都会改变题意。
