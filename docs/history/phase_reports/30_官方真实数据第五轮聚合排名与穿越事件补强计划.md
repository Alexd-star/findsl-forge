## 3. 本轮已实现的能力

### 3.1 聚合排名 `rank(..., agg_func, count_exp)`

官方样例中常见类似：

```text
rank('', '', '成交量', 'desc', '', '', 'GROWTH_RISE', 'CONS=10日') <= 20%
rank('', '', '集合竞价金额', 'asc', '2023年', '', 'AVG', 'CONS=每年') <= 10
```

这类语义不是简单日排名。更准确的编译过程是：

1. 根据 `date` 和 `count_exp` 单位把行情行分到日、周、月、季度或年桶；
2. 对每只股票在每个桶内计算聚合值，例如 `AVG(volume)`、`GROWTH_RISE(volume)`；
3. 在每个桶内按聚合值做 `ROW_NUMBER()` 排名；
4. 对当前股票统计有多少个桶满足名次条件；
5. 用 `CONS/EXIST` 判断桶数量或“每个桶都满足”。

该方案已经在 `src/findsl/official_slot.py` 中实现。SQL 使用 Doris 的 `DATE_TRUNC()`、`ROW_NUMBER()`、`COUNT() OVER`、`MIN_BY()`、`MAX_BY()`。这些都是 Doris 已支持的 SQL 能力，不需要新增伪表。新增测试覆盖了日桶增长率百分位排名和年桶均值排名。

### 3.2 穿越事件 `cross_above/cross_down/golden_cross(..., count_exp)`

官方样例中还有：

```text
cross_above('', '', '最新价', '60日均线', '上周开始4日', '', 'CONS=每日') = True
cross_down('', '', '收盘价', '10日均线', '本月', '', 'CONS=5日') = True
golden_cross('', '', '5日均量线', '10日均量线', '近10个交易日', '', 'EXIST=2日') = True
```

这类语义可以拆成每日事件：

1. 对每只股票按 `bizdate` 排序；
2. 计算当日左值、右值，以及前一交易日左值、右值；
3. `cross_above` 等价于当日左值大于右值，前一日左值小于等于右值；
4. `cross_down` 等价于当日左值小于右值，前一日左值大于等于右值；
5. `golden_cross` 在本项目中沿用上穿口径；
6. 再对事件布尔值套用 `EXIST/CONS`。

该方案已经在 `src/findsl/official_slot.py` 中实现。编译器会先生成 `event_rows` 子查询，把 `LAG()` 计算出的穿越事件物化为 `event_value`，再交给统一的 `count_exp` 子查询处理。这样比把窗口函数直接塞进 WHERE 更稳，也便于解释“窗口内发生几次金叉/上穿/下穿”。

### 3.3 日期与指标细节补强

本轮还补了两个容易被评委追问的细节。

第一，官方样例中存在 `过去20天`、`30个交易日`、`三个月之内`、`近半年` 等口语化时间表达。`src/findsl/official_time.py` 已经把这些表达归一为明确日期窗口，避免生成 `1=1` 这种过宽条件。

第二，官方样例使用 `涨停价`、`跌停价`，而真实基础行情表中对应的是涨停/跌停封单价字段。项目已把 `涨停价` 映射到 `upSealPx`，把 `跌停价` 映射到 `downSealPx`，并保留价格字段统一除以 `10000.0` 的人类单位转换。

第三，`count_exp` 表达式比较现在允许“可无 warning 归一到同一日期范围”的同义日期。例如 `30个交易日内` 与 `30个交易日` 归一到同一窗口后，可以在同一个计数比较中使用；未知时间词仍按原文区分，避免误合并。

## 4. 暂不实现项

以下项继续保持显式不支持：

1. `CONS=1-2月`、`CONS=3-7月`、`CONS=30日-60日`、`EXIST=2-5` 等区间次数表达。它们缺少官方明确解释，且涉及“连续长度范围”与“出现次数范围”的不同口径。
2. `CONS=10分钟`。官方数据是日频行情和集合竞价字段，没有分钟级 K 线。
3. `rank(..., indicator_name='', count_exp)`。没有排名指标时只能表达任意排序或代码排序，官方语义不稳定。
4. 需要财务、公司治理、控股股东、布林线、MACD/DIF、基金/指数等外部数据的样例。
