# 官方真实数据第四轮深度解剖与连续语义补强计划

生成时间：2026-06-10

## 1. 当前判断

本轮重新核查官方资料后，可以确认赛题组目前给出的真实数据只有三张 Doris CSV 表和一份 DSL 训练语料：

| 资料 | 当前规模 | 对项目的意义 |
|---|---:|---|
| `hsj_stock_code_info.csv` | 5,686 行、17 列 | 股票代码、市场、名称、行业、ST、沪深港通、科创/创业标识 |
| `hsj_stock_hq_basic.csv` | 13,650,347 行、56 列 | A 股日行情、价格、成交量、换手率、估值、涨跌停、支撑压力等基础指标 |
| `hsj_stock_hq_ext.csv` | 6,170,822 行、64 列 | 集合竞价、资金流、主力行为、筹码形态、创新高低、连涨连跌等衍生指标 |
| `选股提槽实例.xlsx` | 5,799 条 DSL 样例 | 官方自然语言到 DSL 的训练/验收风格样本 |

因此，后续开发必须坚持一个原则：只对三张官方表能证明的数据域继续扩展；没有数据来源的财务报表、基金、指数成分、用户持仓、公司画像、龙虎榜等，不伪造 SQL，不做硬编码结果，而是保留结构化诊断。

## 3. 第四轮缺口解剖

本轮重点抽取剩余 `UNSUPPORTED_OFFICIAL_COUNT_EXP` 和 `UNSUPPORTED_OFFICIAL_PERIOD_FUNCTION` 两类语义型缺口。统计结果如下：

| 缺口类型 | 数量 | 根因 |
|---|---:|---|
| `UNSUPPORTED_OFFICIAL_COUNT_EXP` | 56 | `CONS/EXIST` 出现在 rank 百分位、四则表达式、聚合排名或无法解析的非标准次数单位中 |
| `UNSUPPORTED_OFFICIAL_PERIOD_FUNCTION` | 18 | `record_high/record_low/position` 同时带 `count_exp`、聚合函数或复杂周期 |

进一步拆开看，仍有一部分必须保留为不支持：例如 `CONS=0.5年`、`CONS=3-7月`、`CONS=10分钟`、`rank(..., agg_func, count_exp)`。这些不是简单代码遗漏，而是需要额外物化特征表或分钟级/财报级数据，否则会出现语义误报。

但也有一批可以继续补齐：

1. `rank(..., count_exp) between '[5%,10%]'`  
   当前编译器支持 `rank(..., count_exp) <= 3`，但还没有支持排名区间，尤其是百分位区间。官方说明允许 between 表达区间，rank 百分位也经常出现在选股问法里。

2. `indicator(..., count_exp) / indicator(..., count_exp) > 常量`  
   官方样例中经常把 `count_exp` 放在算术表达式内部，例如“近 5 周存在 6 日内盘 / 每手股数 > 2000”。这类语义不应该把带 `count_exp` 的 indicator 当成一个普通标量，而应该把整个算术谓词放进时间窗口，统计满足谓词的桶或交易日。

3. `position(..., count_exp) = '低'`、`record_high(..., count_exp) = True`  
   `position/record_high/record_low` 本身已经可以基于价格、成交量、资金等指标计算，但遇到 `count_exp` 时还直接拒绝。对三表可支持的指标，可以把“某日是否处于低位/创新高/创新低”作为窗口内谓词，再统计出现或连续情况。

4. `CONS` 语义从“满足次数”升级为“连续段长度”  
   当前部分路径对 `CONS=3日` 采用窗口内满足次数阈值，并通过 warning 标明“严格连续需要特征表”。从竞赛质量看，这会被评委追问。更稳妥的方案是在 SQL 子查询里用 `ROW_NUMBER()` 构造连续段：先筛出满足谓词的日期，再用日期序号减去行号形成连续段分组，最后计算最长连续段长度。

## 4. 参考资料与技术依据

本轮实现使用的是通用 SQL 编译与 Doris 可执行 SQL 设计思路，重点依赖：

- Apache Doris 官方 SQL/窗口函数能力：`ROW_NUMBER()`、`COUNT() OVER`、`LAG()`、`DATE_TRUNC()` 可支撑排名、桶化和连续段识别。
- Apache Doris 表设计能力：官方数据给出的 `UNIQUE KEY`、`DISTRIBUTED BY HASH` 与列式存储适合按 `mktcode/tgtcode/bizdate` 做股票时间序列查询。
- 查询优化常识：对长窗口和重复计算，优先使用前缀表、物化特征表或预计算列；对单条 DSL 的小窗口谓词，可以用相关子查询和窗口函数表达清楚语义。

## 5. 本轮开发目标

本轮不追求表面上的“全量 5799 全编译”。目标是提高可证明的真实覆盖，并修正可能被追问的语义薄弱处。

| 目标 | 开发动作 | 验收方式 |
|---|---|---|
| 支持 rank 区间与百分位区间 | 扩展 rank predicate 生成逻辑，支持 `between` 和百分位阈值 | 新增单元测试；官方覆盖率重新统计 |
| 支持 count_exp 嵌入算术表达式 | 识别比较表达式中的同源 count_exp，将完整谓词下推到窗口子查询 | 新增内盘/每手、收盘价/均线、成交量/每手样例测试 |
| 支持 period 函数 count_exp | 对 `record_high/record_low/position` 的比较条件做窗口化统计 | 新增 position 连续低位、record_high 连续创新高测试 |
| 修正 CONS 连续语义 | 将非“每日/每周/每月”类 CONS 的阈值统计升级为最长连续段 | 测试 SQL 中出现连续段分组逻辑，不再只看 COUNT |
| 保持缺数据诊断真实 | 对缺失数据域继续返回 `UNSUPPORTED_OFFICIAL_INDICATOR` | 官方负例与 readiness 不回退 |

## 6. 不做的内容

以下内容本轮不开发：

1. 财务报表、基金、指数成分、用户持仓、港美股等字段映射。原因是当前官方 CSV 没有对应表。
2. 分钟级 `CONS=10分钟`。原因是官方数据是日频行情和少量集合竞价字段，没有分钟级 K 线。
3. `rank(..., agg_func, count_exp)` 的高性能物化表。原因是它需要设计 `hsj_stock_rank_feature_daily/monthly` 之类的新特征表，并用 Doris 集群验证存储与刷新成本；可以作为后续亮点，但不应在没有充分验证时仓促合入。
4. 非标准区间次数如 `CONS=3-7月`、`EXIST=2-5`。原因是官方说明没有明确定义区间次数的闭区间、单位折算和连续口径。

## 8. 预期效果

本轮完成后，项目的竞争力主要体现在三点：

第一，官方真实数据的适配不再停留在基础指标映射，而是能处理较复杂的“窗口内出现/连续/排名/位置”组合问法。第二，`CONS` 语义会从近似统计提升到连续段语义，减少答辩时被质疑“连续不等于次数”的风险。第三，项目仍然明确拒绝没有数据来源的字段，表现出数据治理和工程边界意识，这比伪造全覆盖更适合严肃评审。

## 9. 开发后复核结果

本轮实现后重新读取官方 `选股提槽实例.xlsx` 全量 5,799 条样例，结果如下：

| 指标 | 本轮开发前 | 本轮开发后 | 变化 |
|---|---:|---:|---:|
| Doris SQL 可落地编译 | 1,824 | 1,844 | +20 |
| 全量样例可落地编译率 | 31.45% | 31.80% | +0.35 个百分点 |
| 解析成功样例可落地编译率 | 31.49% | 31.84% | +0.35 个百分点 |
| `UNSUPPORTED_OFFICIAL_COUNT_EXP` | 56 | 45 | -11 |
| `UNSUPPORTED_OFFICIAL_PERIOD_FUNCTION` | 18 | 1 | -17 |

这个结果符合本轮目标：不是把没有数据来源的财务、基金、指数、账户类语义“假装支持”，而是把官方行情三表能够支撑的连续、出现、排名区间和位置类语义继续补实。`UNSUPPORTED_OFFICIAL_INDICATOR` 的绝对数量略有上升，是因为原先被 `count_exp` 或 `period_function` 拦住的一些样例继续向下编译后，暴露出了更深层的缺字段问题。例如样例中同时包含 `MACD金叉`、`横盘天数`、`未分配利润` 等当前三表没有字段来源的指标，这些必须保留为缺数据诊断。

本轮新增能力包括：

| 能力 | 实现方式 | 赛题价值 |
|---|---|---|
| rank 区间/百分位区间 | `ROW_NUMBER()` + `COUNT(*) OVER` 计算名次与分区总量，百分位边界用 `CEIL(partition_count * percent / 100)` 转换 | 支持“排名在 5%-10% 之间”等官方样例 |
| 算术表达式内 `count_exp` | 将完整比较谓词下推到时间窗口子查询，而不是把带 `count_exp` 的 indicator 错当成普通标量 | 支持“内盘/每手股数在窗口内出现 N 次满足阈值” |
| period 函数 `count_exp` | 将 `record_high/record_low/position` 的每日判断结果作为窗口内谓词，再统计出现或连续情况 | 支持“连续低位”“多日创新高/新低”等问法 |
| 严格连续段 SQL | 使用 `ROW_NUMBER()` 与 `DATEDIFF()` 构造连续日期分组，计算 `MAX(run_length)` | 把 `CONS=N日` 从近似次数统计提升为连续段判断 |

剩余的 45 个 `UNSUPPORTED_OFFICIAL_COUNT_EXP` 主要集中在三类：带聚合函数的排名时序特征、非标准次数区间和分钟级窗口。剩余 1 个 `UNSUPPORTED_OFFICIAL_PERIOD_FUNCTION` 属于仍需额外特征或字段定义的复杂周期组合。后续如果赛题组继续提供更丰富的字段，可以再设计物化排名特征表；在当前真实数据条件下，继续强行扩展容易牺牲正确性。
