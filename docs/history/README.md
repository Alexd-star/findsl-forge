# 历史文档区

本目录保存已经完成、被替代或只用于解释历史过程的材料。归档不是删除：文件继续纳入 Git，可查询、比较和回溯，但不再与当前开发文档并列展示。

## 状态定义

| 状态 | 含义 | 使用方式 |
| --- | --- | --- |
| 只读参考 | 记录某个阶段的输入、决策、实验和结果。 | 可用于追溯，不可直接作为当前指标。 |
| 已替代 | 已有新的统一文档或实现取代。 | 仅用于理解演进原因。 |
| 历史证据 | 结果真实，但对应旧 Git HEAD、旧配置或旧数据快照。 | 必须显式标注版本，不能进入当前汇总。 |

## 目录说明

- `phase_reports/`：官方真实数据适配、语义补强、迁移和性能阶段报告。
- `legacy_plans/`：被 `docs/00_当前开发主线.md` 取代的旧架构、开发与 UI 计划。
- `implementation_records/`：早期逐阶段设计稿和实施计划，保留技术决策演进。

## 归档规则

1. 当前有效规范、部署手册和验收说明不得移入历史区。
2. 新阶段完成后，先把稳定结论合并到当前主线或对应正式规范，再归档阶段文档。
3. 历史报告中的测试数、Git HEAD 和性能数字不得自动复制到当前报告。
4. 任何移动都通过 Git 完成，不以删除历史来制造“整洁”。
5. 若历史方案重新启用，应先形成新的 ADR 或更新当前主线，不能直接恢复旧文件的权威地位。
