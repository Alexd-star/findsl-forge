# 第23章 官方真实数据二次解剖与技术形态函数补强

本文记录 2026-06-10 在官方真实数据、官方 `选股提槽实例.xlsx` 和当前代码实现基础上的第二轮深度复核。它的目的不是把完成度写得好看，而是回答三个关键问题：第一，当前比赛阶段官方真实数据到底能支持哪些能力；第二，项目距离赛题满分口径还差在哪里；第三，本轮新增的 `reset`、`close_together` 技术形态函数到底解决了什么、没有解决什么。

## 23.1 当前阶段的真实边界

本阶段已经确认，官方赛题组提供的可执行数据只有三张 A 股行情相关表：`hsj_stock_code_info`、`hsj_stock_hq_basic`、`hsj_stock_hq_ext`。项目在 Doris 中进一步构建了 `hsj_stock_hq_basic_prefix`、`hsj_stock_hq_ext_prefix` 和 `hsj_stock_hq_basic_technical` 三张确定性派生表。也就是说，所有能够自信落地的 SQL，都必须能追溯到这三张原始表或三张派生表。

这个边界非常重要。官方 workbook 里有大量财务报表、基金产品、基金持仓、指数成分、用户自选股、龙虎榜、主营业务、题材热度、KDJ、MACD、BOLL、EXPMA 等表达，但当前数据包并没有对应字段或对应明细表。项目不能为了让覆盖率数字更好看，生成不存在的 SQL 字段。当前的正确做法是：能由三表计算的，就编译成 Doris SQL；不能由三表计算的，给出稳定诊断，并在覆盖率报告中归入缺失数据域。

本轮刷新前，官方 workbook 覆盖率为 `row_count=5799`、`parse_ok=5792`、`compile_ok=1682`、`compile_failed=4110`。其中 `UNSUPPORTED_OFFICIAL_FUNCTION` 为 87 次，细分中 `reset` 为 29 次、`close_together` 为 27 次。这两类函数不是外部财务或基金数据，而是“价格/均线/支撑压力位附近”的技术形态表达，正好可以由当前已有行情表和技术特征表继续补强。

## 23.2 官方样例中的 reset 和 close_together

官方 `reset` 样例主要表达“回踩”“回调到”“回落至某条线附近”。例如：

- `reset('', '', '', '10日均线', '前5天', '', '') = True`，对应“回踩 10 日均线”。
- `reset('', '', '最新价', '10日均线', '7月15日', '', '') = True`，对应“股价回踩 10 日均线”。
- `reset('', '', '5日均线', '10日均线', '30日内', '', '') = True`，对应“5 日线回踩 10 日线”。
- `reset('', '', '', '支撑位', '今天', '', '') = True`，对应“回调到支撑位”。

官方 `close_together` 样例主要表达“粘合”“黏到”“沿着某条线运行”。例如：

- `close_together('', '', '', '20日均线', '', '', '') = True`，对应“20 日均线粘合”，左侧为空时按股价理解。
- `close_together('', '', '5日均线', '20日均线', '', '', '') = True`，对应“两条均线粘合”。
- `close_together('', '', '最新价', '10日均线', '目前', '', '') = True`，对应“股价沿着 10 日均线”。
- `close_together('', '', '', '5日均线', '', '', 'CONS=5日') = True`，对应“连续 5 天沿着 5 日均线”。

这些语义的共同点是：它们不是新的数据域，而是已有数值指标之间的相对距离判断。因此，本轮实现采用“相对距离阈值”而不是“绝对价格差”。同样相差 0.2 元，对 2 元股票和 200 元股票意义完全不同；相对距离才更适合跨股票、跨价格区间的统一口径。

## 23.3 本轮实现方案

本轮新增 `configs/official_technical_patterns.json`，把阈值从编译器代码中剥离出来。默认参数如下：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `close_together.relative_threshold` | `0.03` | 两个数值指标相对距离不超过 3%，视为粘合 |
| `reset.near_line_threshold` | `0.02` | 左指标距离目标线不超过 2%，视为回踩到附近 |
| `reset.below_line_tolerance` | `0.005` | 允许左指标轻微低于目标线 0.5%，避免真实行情噪声造成误判 |

`close_together` 的 SQL 形态为：

```sql
ABS(left - right) / NULLIF(GREATEST(ABS(left), ABS(right)), 0) <= 0.03
```

`reset` 的 SQL 形态为：

```sql
ABS(left - right) / NULLIF(ABS(right), 0) <= 0.02
AND left >= right * (1 - 0.005)
```

左指标为空时，项目按 `最新价` 处理。这符合官方样例中“回踩 10 日均线”“沿着 5 日线”这类自然语言表达，因为没有显式左指标时，业务上通常指股价或当前价格。右指标必须明确存在；如果右指标缺失，编译器不会猜测。

带 `CONS/EXIST` 的技术形态函数，本轮接入窗口计数路径。它会在归一化日期窗口内统计满足形态条件的交易日数量。需要注意，当前 `CONS` 仍沿用项目既有口径：编译为窗口内满足次数阈值，并通过 warning 说明“严格最长连续段检测需要专用 Doris feature table”。这个说法必须保留，因为否则答辩时容易被追问“连续 5 天”和“5 天内出现 5 次”是否完全等价。

新增测试先按 TDD 方式跑出失败，再实现功能后变为通过。测试覆盖了四个关键风险：默认左指标是否按 `最新价` 处理；阈值是否来自配置口径；`False` 是否正确取反；K/D/J 等官方三表没有的数据是否继续报 `UNSUPPORTED_OFFICIAL_INDICATOR`，而不是伪造 SQL。

| 语法解析成功 | 5792 | 5792 | 0 |
| Doris SQL 编译成功 | 1682 | 1718 | +36 |
| Doris SQL 编译失败 | 4110 | 4074 | -36 |

`UNSUPPORTED_OFFICIAL_FUNCTION` 的下降幅度大于 `compile_ok` 的提升，是因为一部分样例从“函数不支持”继续向下解析后，暴露出真实缺失指标，例如 `K值`、`D值`、`EXPMA(50)`、`布林线上轨`、`单位净值`、`主营业务`、`龙头股`、`退市日期` 等。这不是倒退，而是诊断更准确：之前系统只能说“不支持这个函数”，现在可以说“函数已经支持，但这个指标不在官方三表中”。

本轮后，`reset` 与 `close_together` 已不再出现在 `UNSUPPORTED_OFFICIAL_FUNCTION` 的 TopN 中。剩余函数语义缺口主要是 `rank` 的特殊表达形态、复杂 `count_exp`、复杂 parse/expr 边界。

## 23.6 仍需补强的项目

第一，动态 N 日均线仍需谨慎处理。官方样例中出现 `7日均线`、`13日均线`、`25日均线`、`45日均线`、`90日均线`、`610日均线` 等表达，但当前技术特征表只预计算了 MA3/5/10/20/30/60/120/200/250。后续可以基于 prefix 表做动态 N 日均线计算，但必须保证“交易日 N 根 K 线”而不是“自然日 N 天”的口径，否则会在停牌或节假日场景下产生隐蔽错误。

第二，KDJ、MACD、BOLL、EXPMA 等技术指标需要专门特征表。它们不能只靠字符串别名解决，因为需要历史窗口、递推公式和初始化口径。若后续继续冲刺，应新增 `hsj_stock_hq_basic_technical_ext`，逐项定义 K、D、J、DIF、DEA、MACD、BOLL 上中下轨、EXPMA 等字段，并用小样本手工核验公式。

第三，严格连续段检测还没有完全特征化。当前 `CONS` 的多数路径已经能在窗口内做次数阈值，但严格“最长连续满足 N 天”最好建立 run-length feature table。否则对于评委特别追问的“连续”和“出现次数”差别，要说明当前哪些路径是近似、哪些路径是严格。

第四，rank 特征表仍是下一轮高价值优化。官方 workbook 中 `rank` 出现频率高，剩余 `UNSUPPORTED_OFFICIAL_FUNCTION: rank` 为 31 次，且排名窗口在 Doris 中开销较大。下一步建议做 `hsj_stock_rank_feature_daily/monthly`，预计算高频指标的日/月排名，再把 `rank(..., count_exp)` 从现场窗口排序改为查表过滤。

第五，官方缺失数据域要继续文档化。财务、基金、指数、用户持仓、龙虎榜、公司画像等不是当前代码“不会做”，而是没有真实数据来源。提交材料应持续强调这一点，避免把可信诊断误解成未完成。

## 23.8 答辩表达建议

可以这样解释本轮工作：官方语料中有大量“回踩均线”“均线粘合”“股价沿着均线”这样的技术形态表达。早期系统能解析这些函数名，但不能落地成 Doris SQL。本轮我们没有随意硬编码一个口径，而是把形态识别抽象为可配置的相对距离阈值：粘合用两个指标间的相对距离，回踩用当前位置与目标线的相对距离和轻微跌破容忍。阈值放在配置文件里，便于按券商业务口径调整。刷新官方 workbook 后，可落地编译样例从 1682 条提升到 1718 条，函数语义缺口从 87 条降到 31 条。

同时要主动说明边界：如果样例涉及 KDJ、MACD、BOLL、EXPMA、基金净值、财务指标、指数成分或用户持仓，当前官方三表没有对应数据，因此系统会给出缺失指标诊断，而不是生成假 SQL。这一点体现的是数据治理项目的可信边界，而不是逃避实现。
