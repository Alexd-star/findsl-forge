# 05 项目架构说明

FinDSL Forge 采用分层架构，核心思想是把自然语言、DSL、编译、验证、执行和证据生成拆开，避免任何单一模块承担过多职责。

## 1. 总体架构

```text
输入层：DSL / 中文自然语言 / LLM 候选
  -> 编译前端：lexer、parser、AST
  -> 语义层：semantic、registry、diagnostics
  -> 生成层：sqlgen、doris_sql
  -> 验证层：reference、executor、equivalence
  -> 证据层：benchmark、doris_evidence、readiness、defense_package
  -> 展示层：demo、submission_artifacts
```

## 2. 输入层

输入层接受三类内容：直接 DSL、中文自然语言、LLM 返回文本。自然语言和 LLM 都不会直接进入 SQL 执行，而是先转为 DSL 候选，再由同一套编译器处理。

## 3. 编译前端

`lexer.py` 将字符串拆成 token，`parser.py` 将 token 组装为 AST，`ast_nodes.py` 定义节点结构。这个阶段只负责“表达式长什么样”，不负责业务指标是否存在。

## 4. 语义层

`semantic.py` 与 `registry.py` 校验函数签名、指标、窗口、参数、类型和日期。`diagnostics.py` 把错误变成可读诊断和修复建议。

## 5. SQL 生成层

`sqlgen.py` 把 AST 编译为 Doris SQL。它负责：

- `filter` 外层 WHERE；
- `then` CTE pipeline；
- `rank` 的 ROW_NUMBER；
- `CONS/EXIST/MA/SUM/MAX/MIN/RET` 的窗口特征；
- prefix-sum 优化；
- 日期下推和窗口安全边界；
- 字符串 literal escaping。

`doris_sql.py` 对生成 SQL 做形态校验，防止出现多语句、DDL/DML、未知表或 window-in-WHERE。

## 6. 验证层

`reference.py` 用 Pandas 独立解释 DSL；`executor.py` 把 CSV 加载到 SQLite 并执行生成 SQL；`equivalence.py` 比较两边 `(ts_code, trade_date)` 结果。这个设计可以在 Doris 环境不可用时仍然做快速语义回归。

## 7. 证据层

`benchmark.py`、`scale_benchmark.py`、`doris_evidence.py`、`official_suite.py`、`readiness.py` 和 `defense_package.py` 负责生成性能、正确性、覆盖率和提交证据。最终可提交证据通过 `submission_artifacts/` 管理。

## 8. 展示层

`demo.py` 提供 Web Demo 和 JSON API。它把 DSL 候选、编译结果、AST、SQL、Explain、Rows 和 Evidence 展示给评审或用户。
