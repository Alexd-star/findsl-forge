# 05 项目架构说明

FinDSL Forge 采用编译数据面、配置控制面、证据面和服务面分离的架构。正式产品能力集中在 `src/findsl/official/`，旧手写编译器只承担内部样例、兼容入口和迁移差分，不再新增官方语义。

## 1. 总体架构

```text
官方七槽位 DSL
  -> OfficialSlot.g4 / ANTLR4 frontend
  -> immutable Typed AST
  -> semantic policy binding
  -> financial Domain Model
  -> canonical Relational IR
  -> equivalence rewrite rules
  -> physical candidate planner
  -> cost and risk selector
  -> validated Physical IR
  -> SQLGlot Doris AST / SQL
  -> Doris execution, EXPLAIN and Profile
  -> independent oracle and evidence manifest
```

自然语言和 LLM 只生成 DSL 候选，不能直接生成可执行 SQL，也不能绕开上述链路。

## 2. 编译数据面

### ANTLR 前端

`grammar/OfficialSlot.g4` 是正式语法源，生成解析器位于 `src/findsl/official/frontend/generated/`。`antlr_frontend.py` 负责严格解析和错误位置，`ast_adapter.py` 把解析树转换为项目 AST。恢复模式只处理白名单文本缺陷，并保留原始输入和修复记录。

### 类型与语义

`typed_ast.py`、`semantics.py`、`signatures.py` 和 `policy.py` 检查函数签名、槽位、类型、参数和业务政策。该层回答“表达式是否合法、采用哪一版业务口径”，不选择 Doris 表或拼 SQL。

### 领域模型与关系 IR

`domain/` 把指标、市场范围、时间和事件绑定成金融领域对象；`ir/` 再把领域意图降低为 Scan、Filter、Project、Join、Aggregate、Window、Rank、Stage 和 Set Operation 等正交关系节点。Logical IR 不应包含数据库名、物理表名或 SQL 片段。

### 重写与物理规划

`optimizer/` 保存可证明等价的逻辑规则，规则只产生等价计划和 trace。`physical/` 使用目录、统计、数据新鲜度和风险政策枚举原始窗口、固定特征、prefix、rollup 或物化视图候选，再进行选择。当前规划器已可用，但仍需从固定 pass 顺序继续收敛为轻量 memo 与成本/风险选择。

### Doris 后端

`backend/` 把 Physical IR 转为 SQLGlot Doris AST，并执行单条只读查询、表列白名单、窗口位置、稳定排序和方言往返校验。配置不能注入任意 SQL 字符串。Doris Nereids、统计、分区裁剪和物化视图负责数据库内部优化。

## 3. 配置控制面

控制面管理函数签名、指标、资源、物理策略、范围成员、语义政策和数据快照。每次编译最终应通过 `CompileContext/CatalogSnapshot` 固定所见版本，并记录 catalog fingerprint。在线编译不能临时访问未版本化外部网络数据。

外部数据 Provider 位于 `src/findsl/official/external/`。只有来源、原始响应、快照时间、成员完整性、许可和历史有效期可说明的数据，才能进入正式范围目录。

## 4. 证据面

`official_*_evidence.py`、`official_coverage_funnel.py`、`official_gap_analysis.py`、`evidence_metadata.py` 和 `readiness.py` 负责解析覆盖、独立正确性、真实 Doris 性能、数据治理和提交一致性。证据面不能修改编译规则，也不能把历史结果自动计入当前结论。

正确率、迁移率、解析率和编译成功率分别统计。正式正确性必须由不复用被测 planner 或 renderer 的独立 oracle 比较完整结果行。

## 5. 服务面

`demo.py` 提供 Web Demo 和 JSON API。正式目标是 CLI、API、Demo 和证据脚本共享同一应用服务，不复制编译逻辑。生产化还需补充鉴权、限流、请求预算、可观测性、并发隔离、配置发布、备份和恢复。

## 6. 新旧边界

`official_slot.py`、`compiler.py`、`lexer.py`、`parser.py`、`semantic.py` 和 `sqlgen.py` 是早期实现，当前只作兼容和回归。正式官方核心禁止依赖这些模块，规则由 `import-linter` 和 CI 强制。满足正式正确率、12 类函数矩阵、零代码扩展、自动长周期优化和连续版本回归门禁后，再归档旧管道。

## 7. 当前拆分重点

1. 建立不可变 `CompileContext/CatalogSnapshot`；
2. 进一步分离 Domain IR 与通用 Relational IR；
3. 拆分超大的 physical planner、Doris backend 和 validator；
4. 建立候选 memo、成本向量和风险罚分；
5. 统一 CLI/API/Demo 正式入口；
6. 以独立正确率和分层性能矩阵作为完成门禁。

完整目标与阶段顺序见 [00_当前开发主线.md](00_当前开发主线.md)，长期边界见 [ADR-0001](adr/0001-官方编译器主线与兼容层边界.md)。
