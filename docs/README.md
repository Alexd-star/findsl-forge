# FinDSL Forge 文档导航

`docs/` 只保留当前仍参与开发、验收、部署和答辩的文档。阶段复盘、已完成实施计划和被新方案替代的旧设计统一放在 `docs/history/`，保留追溯价值，但不再作为当前实现依据。

## 唯一开发依据

[00_当前开发主线.md](00_当前开发主线.md) 是后续开发的唯一主控文档。它统一说明官方要求、当前事实、目标架构、能力缺口、阶段顺序、验收口径和“完成”的定义。若其他说明与当前代码或该路线冲突，应先核对赛题原文、当前 Git HEAD 和机器可读证据，再修订文档，不允许继续按旧阶段计划追加补丁。

持久架构决策记录在 [adr/](adr/README.md)。ADR 只记录会长期约束代码边界的决定，不代替开发路线，也不记录每日进度。

## 长篇手册

- `FinDSL_Forge_中文操作手册.md/.docx/.pdf`：正式操作与验收手册。
- `FinDSL_Forge_中文综合操作指南.md/.docx`：面向完整学习和答辩准备的长篇指南。

长篇手册属于最终发布材料，不是当前开发或指标事实源。核心功能、正式正确率、性能矩阵和同 HEAD 证据闭环前暂不刷新；最终封板阶段再集中更新测试数、Git HEAD、性能数字、架构描述和版式，避免重复劳动。

## 推荐阅读顺序

1. 首次了解：根目录 `README.md` → `01_项目简介.md` → `03_操作手册.md`。
2. 继续开发：`00_当前开发主线.md` → `adr/` → 对应模块文档和测试。
3. 核验赛题：`requirement_mapping.md` → `36_严格官方编译基线与口径说明.md` → 机器可读证据。
4. 准备答辩：`17_项目交付说明.md` → `defense_walkthrough.md` → 截图和证据快照。
