# Phase 6A 真实统计驱动成本模型实施计划

## 目标

用 Apache Doris 的真实表统计替换 Phase 5 中固定 `resource.priority` 的估算成本，同时保持规划结果可复现、可审计、可回退。Phase 6A 不引入未经证明的选择率公式，也不提前改变默认 SQL 后端。

## 设计边界

1. 统计来源仅接受 Doris `SHOW TABLE STATS` 和 `SHOW DATA` 的实际输出。
2. 快照记录目录指纹、采集时间、Doris 版本、资源行数、存储字节数和分析状态。
3. 快照与当前物理目录指纹不一致时拒绝使用，不静默降级为“真实成本”。
4. 单资源计划成本定义为主资源与必要锚资源的预计扫描字节数之和；未知分区数、列基数和过滤选择率不参与公式。
5. 缺少统计时继续使用目录优先级，并明确 `estimated=True`，保证离线编译可用。
6. 本阶段先建立稳定统计接口。前缀表与多物理映射在 Phase 6B 复用该接口进行候选排序。

## TDD 任务

### 任务 1：版本化统计快照

- 新增 `official/physical/statistics.py`。
- 红测覆盖合法加载、重复资源、负数统计、目录指纹错配和确定性序列化。
- 实现冻结数据类、严格字段校验和目录兼容性检查。

### 任务 2：统计驱动成本

- 为 `plan_physical` 增加可选统计快照。
- 红测证明基础表成本只含自身字节数，扩展表成本包含基础锚表，缺少任一统计时回退为估算。
- 决策轨迹必须说明成本来源和组成，不使用无法证明的选择率。

### 任务 3：Doris 统计采集器与 CLI

- 新增只执行受控元数据命令的采集器，不复用仅允许 SELECT 的结果执行器。
- 红测覆盖 MySQL 参数、密码脱敏、表统计解析、KB/MB/GB/TB 单位换算和失败输出。
- 增加 `official-physical-stats` 命令，输出 JSON 快照。

### 任务 4：真实快照与回归

- 从当前官方 Doris 环境采集四张受控资源的真实快照。
- 更新中文后端说明和 README，明确成本模型可证明与不可证明的边界。
- 运行 ANTLR 检查、全量 pytest、`git diff --check`，提交并通过代理推送。

## Phase 6B 接口预留

Phase 6B 将物理目录从“一个指标一个字段”扩展为“一个逻辑指标多个物理实现”，加入基础窗口、前缀自连接和热点物化列候选。所有候选必须复用 Phase 6A 快照、决策轨迹和真实 Doris 结果哈希，不另建不可审计的启发式路径。
