# Phase 28 官方事件默认价格语义

## 问题来源

官方工作簿保留了大量省略价格主语的槽位。例如“刚好突破 60 日均线”写成 `cross_above('', '', '', '60日均线', ...)`，“今年创史低”写成 `record_low('', '', '', '历史', '今年', ...)`，“低位、多次放量”写成 `position('', '', '', '', ...)='低'`。这些空槽位不是未知指标，而是自然语言已经把主语隐含为股票价格。

旧严格后端在部分路径中使用 `最新价`，新 ANTLR/IR 后端此前却在 Domain Binder 直接拒绝，导致同一官方合同在两条编译链中含义不一致。不能在物理层逐个补丁式猜值，因为那会让 Logical IR 和执行 SQL 的语义证据不一致。

## 规范化合同

本阶段在领域绑定入口统一执行以下受控规则：

| 函数 | 允许缺省的槽位 | 规范化值 |
|---|---|---|
| `cross_above/cross_down` | `indicator_name_1` | `最新价` |
| `close_together/reset` | `indicator_name_1` | `最新价` |
| `record_high/record_low/position` | `indicator_name` | `最新价` |

规则只覆盖官方问句能够从自然语言反推价格主语的函数。`indicator_name_2` 仍必须明确，`rank` 与 `queryData` 的空指标仍然拒绝；`golden_cross` 没有相同的官方空槽样例，因此也不加入默认值。原始 Typed AST 保留用户输入，Logical IR 的 `FunctionBinding.slots` 记录规范化结果，使“输入是什么”和“执行了什么”都可追踪。

## 实现与验证

`normalize_function_slots` 是唯一规范化入口，Binder 用它解析指标和数据需求，Lowering 用同一函数重建 Logical IR binding。物理规划器不再承担默认值推断，只消费已经绑定的明确指标。

官方全量漏斗从 `690/1097` 提升到 `729/1097`，新增 39 条均来自旧严格成功集。审计器逐条确认：Logical IR 中存在 `最新价`，Doris SQL 真实引用 `lastPx/10000.0`，事件算子被物化，不含 `1=0/1=1` 占位，并通过 SQLGlot AST 与安全校验。

真实 Doris 证据覆盖股价上穿均线、未下穿均线、五交易日新低、历史低位、接近 20 日均线和回踩 5 日均线。六组结果全部非空，与独立参考 SQL 的完整 `(mktcode,tgtcode,bizdate)` 结果集 SHA-256 一致 `6/6`，结构合同 `6/6`，最高三轮 P95 约 3.60 秒。

## 边界

本阶段解决的是官方槽位中的省略主语，不是通用缺失值填充。概念、行业、指数和自定义板块成员关系仍因数据缺失而拒绝；空排名度量仍然没有可定义的排序键。任何后续默认值都必须先在官方自然语言与槽位对照中找到可复核依据，再进入这一规范化表。
