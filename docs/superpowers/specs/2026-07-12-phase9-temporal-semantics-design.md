# Phase 9：交易序列时序语义与集合式 Doris 计划设计

## 1. 目标

Phase 9 将官方 `count_exp` 从函数槽位中的普通字符串升级为编译器可验证的时序合同，并为 `CONS`、`EXIST`、`每年/每月/每日`建立严格的 Logical IR、Physical IR 与 Doris SQL 计划。实现必须保持交易序列语义，不使用自然日差近似交易日连续性，也不把连续出现退化为窗口内总次数。

## 2. 语义合同

`TemporalQuantifier` 保存：

- 模式：`CONS` 或 `EXIST`；
- 比较符：`< <= = != > >= between`；
- 下界、可选上界；
- 年、季度、月、周、日或分钟单位；
- `每`语义；
- 原始文本；
- `trading_sequence=true` 证明义务。

默认规则遵循官方说明：未指定次数的连续语义为 `CONS>1`，存在语义为 `EXIST>0`。`每`必须携带单位，范围上界不得小于下界，连续长度必须为正数。小数单位在没有明确业务换算策略时拒绝，不采用近似天数换算。

## 3. 逻辑语义

原子比较：

```text
indicator(..., count_exp='CONS=3日') > 0
```

降低为：

```text
LogicalConsecutive(
  input = LogicalDomainScan(...),
  spec = ConsecutiveSpec(predicate = indicator(...) > 0, threshold = 3, unit = 日)
)
```

行谓词保存在时序节点内部，不能先过滤输入关系再计算连续段，否则不满足条件的交易日会被删除，剩余行会被错误拼接为连续序列。多个带独立 `count_exp` 的函数必须建立独立关系分支再按稳定股票键连接；在该能力完成前返回明确诊断，不把整个复合布尔条件错误地套用到一个时序窗口。

## 4. Doris 物理计划

### 4.1 EXIST

1. 在受日期范围约束的历史行上计算一次行谓词；
2. 按 `(mktcode,tgtcode)` 分组；
3. 日粒度统计匹配交易行，年/季度/月/周先按日历桶归并；
4. 对匹配桶数应用比较合同；
5. 与锚点快照按稳定股票键连接，输出 `(mktcode,tgtcode,bizdate)`。

### 4.2 CONS

日粒度采用交易行序号岛屿法：

1. 按 `(mktcode,tgtcode)` 和 `bizdate` 排序；
2. 为完整交易序列生成 `ROW_NUMBER()`；
3. 对满足谓词的行再次生成匹配序号；
4. 用两者差值标识连续岛；
5. 统计每个岛长度，并按合同筛选股票。

该方法以实际交易记录顺序为准，周末和法定节假日不会制造假断点。年/季度/月/周的连续性在聚合桶序列上执行，并显式处理空桶策略。

### 4.3 每桶语义

`CONS=每年` 或 `EXIST=每年`要求窗口非空，且有效桶总数等于匹配桶数。空窗口不得因 `0=0` 被判定为通过。

## 5. 正确性门禁

- parser、Domain IR、Physical IR 均不得保存 SQL 片段；
- 所有 temporal SQL 必须由 SQLGlot AST 构造；
- 日连续性不得使用 `DATEDIFF(date,'1970-01-01')`；
- `CONS` 不得编译为普通 `COUNT(*)` 阈值；
- 窗口函数不得出现在同层 `WHERE`；
- 真实 Doris 对照必须比较稳定行集哈希；
- hash 不一致、执行错误或超时均不得计入正确案例；
- 只有同一数据快照、同一结果哈希和重复测量下才报告加速比。

## 6. 迁移顺序

1. Typed Temporal Contract 与稳定诊断；
2. 原子 `EXIST` 日粒度；
3. 原子 `CONS` 日粒度交易序列；
4. 年/季度/月/周桶；
5. `agg_func + count_exp`；
6. 多时序谓词独立 CTE/Join；
7. temporal rank 与多阶段 `then`；
8. 与技术特征表、prefix、物化视图进行成本候选比较。

## 7. 非目标

- 不复制旧后端的近似连续次数实现；
- 不为了提高覆盖率接受缺失数据域；
- 不把相关标量子查询直接包装进新后端；
- 不在真实 Doris 证据前激活新的性能策略。
