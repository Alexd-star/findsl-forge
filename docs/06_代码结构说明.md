# 06 代码结构说明

本文说明源码、配置、测试、脚本和证据目录的职责。完整文件索引见 [PROJECT_INDEX.md](../PROJECT_INDEX.md)。

## 1. 正式源码

```text
src/findsl/official/
├── pipeline.py          # 正式编译编排
├── ast.py               # 前端统一 AST
├── typed_ast.py         # 不可变 Typed AST
├── semantics.py         # 类型与签名检查
├── policy.py            # 业务语义政策
├── registry.py          # 官方指标/资源目录
├── frontend/            # ANTLR 前端与 generated parser
├── domain/              # 金融领域绑定
├── ir/                  # SQL 无关关系 IR
├── optimizer/           # 等价规则与 trace
├── physical/            # 目录、统计、候选和 Physical IR
├── backend/             # SQLGlot Doris AST、校验和执行
└── external/            # 版本化外部数据 Provider
```

`src/findsl/official_*_evidence.py`、`official_coverage_funnel.py`、`official_gap_analysis.py`、`evidence_metadata.py` 和 `readiness.py` 属于证据与交付支持，不应承载编译业务规则。

## 2. 兼容源码

`src/findsl/compat/official_frontend/` 保存迁移期手写前端和 ANTLR/手写差分；`official_slot.py`、`compiler.py`、`lexer.py`、`parser.py`、`semantic.py`、`sqlgen.py` 和 `ast_nodes.py` 是早期内部管道。它们继续服务内部样例和迁移回归，但不再新增官方能力。import-linter 禁止 `src/findsl/official/` 反向依赖这些模块。

## 3. 配置

- `configs/official/`：正式指标、物理资源、范围、策略和后续语义/证据合同。
- `configs/indicators.json`、`functions.json`、`tables.json`：内部 FinDSL 与历史兼容配置。

配置只保存声明和受控代数，不保存密钥、机器路径或任意可执行 SQL。正式发布配置需要 Schema、版本和 fingerprint。

## 4. 测试

- `tests/official/frontend/`：ANTLR 严格/恢复解析、适配和 parity。
- `tests/official/domain/`、`ir/`、`optimizer/`、`physical/`、`backend/`：各正式阶段测试。
- `tests/official/test_pipeline.py`：正式端到端阶段和错误边界。
- `tests/test_official_gap_analysis.py`：5799 条能力分类和迁移缺口口径。
- `tests/test_equivalence.py`、reference/Doris evidence 测试：结果等价与证据。
- 其他 `tests/test_*.py`：内部 FinDSL、Demo、部署、readiness 和提交兼容回归。

新增正式能力应首先进入 `tests/official/`，再按需要补全局回归。

## 5. 脚本

`scripts/` 只负责调用产品模块、环境编排、数据同步、证据生成、文档和交付。脚本不应复制 parser、planner 或 SQL renderer 逻辑。`analyze_official_gaps.py` 是能力聚类入口，`generate_antlr.py` 是 grammar generated 源校验入口。

## 6. 数据、报告与交付

- `data/samples/`：小型确定性测试数据；
- `data/real_samples/`：带来源的公开样例；
- `data/generated/`：可再生成规模数据，默认忽略；
- `deploy/doris/`：Doris schema、导入、构建和 smoke 资产；
- `reports/`：本地可再生成结果；
- `submission_artifacts/`：评委可查看的轻量证据和提交材料；
- `docs/history/`：阶段报告、旧计划和历史实施记录。

## 7. 文档

`docs/00_当前开发主线.md` 是唯一开发路线，`docs/adr/` 记录长期架构决定，`docs/01_*` 至 `17_*` 是当前产品文档，赛题专项规范和长篇手册继续位于 `docs/`。新阶段复盘完成后应迁入 `docs/history/`，不要继续在根层累加 Phase 文档。
