# 06 代码结构说明

本文档说明源码、测试、脚本和配置的结构关系。更完整的文件级索引见 [../PROJECT_INDEX.md](../PROJECT_INDEX.md)。

## 1. 源码结构

```text
src/findsl/
├── lexer.py              # 词法分析
├── parser.py             # 语法分析
├── ast_nodes.py          # AST 节点
├── semantic.py           # 语义校验
├── sqlgen.py             # Doris SQL 生成
├── compiler.py           # 编译器入口
├── reference.py          # Pandas reference
├── executor.py           # SQLite 本地执行
├── equivalence.py        # SQL/reference 对比
├── doris.py              # Doris SQL 资产生成
├── doris_sql.py          # SQL 安全验证
├── doris_evidence.py     # Doris 证据采集
├── nl2dsl.py             # 中文模板转 DSL
├── llm_adapter.py        # LLM 候选提取与验证
├── llm_provider.py       # Provider 调用
├── demo.py               # Web Demo
├── readiness.py          # 提交门禁
└── cli.py                # 命令行入口
```

## 2. 配置结构

`configs/` 中的 JSON 文件是业务扩展的第一入口。`Registry` 负责加载这些配置，并向 semantic、sqlgen、doris asset generator 提供统一元数据。

## 3. 测试结构

`tests/` 按功能拆分。核心测试包括：

- `test_parser.py`：语法解析。
- `test_semantic.py`：语义规则。
- `test_compiler.py`：SQL 生成片段。
- `test_equivalence.py`：SQL/reference 等价。
- `test_doris.py`、`test_doris_sql.py`：Doris 资产和 SQL 形态。
- `test_readiness.py`：提交门禁。
- `test_demo.py`：Web Demo API。
- `test_llm_adapter.py`、`test_llm_provider.py`：AI 辅助安全边界。

## 4. 脚本结构

`scripts/*.ps1` 是 Windows 友好的快捷入口；Python 脚本用于真实样本抓取、中文文档生成和答辩视频生成。脚本不应包含核心业务逻辑，核心逻辑应放在 `src/findsl/` 中，脚本只负责调用。

## 5. 产物结构

- `reports/`：本地生成报告，忽略提交。
- `submission_artifacts/`：最终提交包和证据快照，可提交。
- `deploy/doris/`：可复现部署资产，可提交。
- `data/generated/`：生成数据，忽略提交。
