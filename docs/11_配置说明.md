# 11 配置说明

FinDSL Forge 的业务扩展主要依赖 `configs/` 目录。配置文件采用 JSON 格式，启动时由 `Registry` 加载。

## 1. `functions.json`

定义 DSL 函数签名，例如最小参数数、最大参数数、允许命名参数和返回类型。

示例：

```json
{
  "rank": {
    "min_args": 2,
    "max_args": 2,
    "named_args": ["top", "bottom", "percent"],
    "return_type": "relation"
  }
}
```

函数配置分为两类。第一类是核心语义函数，例如 `filter`、`then`、`rank`、`CONS`、`EXIST`、`SUM`、`RET`，这些函数涉及关系构造、窗口状态或优化路径，仍然需要 `semantic.py`、`sqlgen.py`、`reference.py` 和测试共同维护。第二类是简单数值模板函数，例如当前的 `ABS`。这类函数可以在 `functions.json` 中声明 `arg_types`、`sql_template` 和 `reference_op`，由通用模板路径完成类型检查、SQL 生成和 reference 计算。

`ABS` 的配置示例如下：

```json
{
  "ABS": {
    "min_args": 1,
    "max_args": 1,
    "return_type": "numeric",
    "arg_types": ["numeric"],
    "sql_template": "ABS({arg0})",
    "reference_op": "abs",
    "category": "template_numeric_scalar"
  }
}
```

这条配置说明：`ABS` 接收一个数值参数，SQL 生成时把参数放入 `ABS({arg0})`，reference evaluator 使用 `abs` 运算。该能力用于支撑赛题中“新函数接入时核心编译引擎代码 0 行改动”的一部分要求。需要注意的是，当前模板函数适合简单数值标量函数；如果新增函数涉及窗口、关系阶段、布尔状态机或 Doris 物化路径，仍应补充专门的语义规则、SQL 生成规则、reference 规则和测试。

## 2. `indicators.json`

定义金融指标。每个指标包含类型、逻辑表、列名、复权口径、是否支持 prefix-sum 等信息。

如果新增普通数值指标，通常只需添加指标配置和样本数据；如果支持 prefix-sum，还要配置 prefix table 和 prefix column。

## 3. `tables.json`

定义逻辑表和 Doris 物理表之间的映射，包括物理表名、别名、日期列、证券代码列和分区列。

修改表配置会影响：

- SQL 生成；
- Doris DDL；
- prefix 表构建；
- SQL validator 允许表清单；
- 测试样本加载。

## 4. 配置维护建议

1. 修改配置后运行 `python -m pytest tests/test_config_extension.py tests/test_template_functions.py tests/test_compiler.py -q`。
2. 新增表或字段后同步更新 `data/samples/`。
3. Doris 表名或字段名变更后重新执行 `scripts/generate_doris_assets.ps1`。
4. 配置文件不要存放账号、密码、API Key 或本机路径。
