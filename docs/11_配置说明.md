# 11 配置说明

FinDSL Forge 同时保留正式官方配置和早期内部 FinDSL 配置。两者用途不同，不能用内部模板能力替代官方主链路的零代码扩展证据。

## 1. 正式官方配置

`configs/official/` 管理官方指标、物理资源、范围目录、候选策略和后续语义/证据合同。配置由 `src/findsl/official/registry.py`、`physical/catalog.py`、`physical/strategies.py` 和 `external/` 加载。

正式配置必须满足：

- 有 JSON Schema 或等价结构校验；
- 有 schema version、业务 version 和内容 SHA-256；
- 一次编译绑定一个不可变 catalog fingerprint；
- 指标列、Doris 资源和数据域真实存在；
- 外部范围记录来源、快照时间、成员数、有效期和审核状态；
- 表达式只使用受控操作符代数，不能注入任意 SQL；
- 未审核政策标记 `provisional`，不能包装成官方定义。

后续统一增加 `semantic_policies.json`，管理排名并列、复权、周期、近似、位置分档、NULL、日历和范围历史政策；增加 `evidence_contract.json`，约束指标名称、分子、分母、HEAD 和数据快照。

## 2. 指标扩展

普通指标配置至少包含名称、值类型、数据域、资源、列、可用日期和物理能力。新增后必须验证：

1. Registry 可解析；
2. Typed AST 类型正确；
3. Logical/Physical IR 绑定到受控资源；
4. SQLGlot 后端生成安全 SQL；
5. 真实 Doris 非空执行并与独立 oracle 一致；
6. 冻结核心源码前后哈希相同。

若指标依赖新表，不能只添加列名，还要补 Catalog、DDL/导入、统计、数据快照和 Provider。

## 3. 函数扩展

正式目标是配置化函数目录与受控模板协议：

- 标量模板：参数类型、返回类型和白名单表达式；
- 聚合/窗口模板：partition/order/frame、空值和除零政策；
- 事件模板：状态转换、观察窗口和时间政策；
- 物理策略：适用条件、所需资源、成本特征和回退。

无法由协议表达的新关系语义仍需新增 IR 算子。“零代码”指协议覆盖范围内零核心修改，不意味着配置可以创造任意算法。

## 4. 早期兼容配置

根层 `configs/functions.json`、`indicators.json` 和 `tables.json` 主要服务内部 FinDSL。`functions.json` 中 `ABS` 的 `sql_template/reference_op` 证明简单数值模板路径可行，但当前不构成正式官方函数扩展闭环。该配置仍需维护兼容测试，不再作为新增官方复杂时序函数的开发入口。

## 5. 外部数据配置

公开或第三方数据只能通过 Provider 接入。正式快照至少保存 provider ID、源 URL/文件、许可说明、抓取时间、原始响应哈希、标准化成员哈希、成员数、别名审核和 effective_from/effective_to。只有当前成员而无历史成员时，不能回答历史日期范围。

## 6. 安全与发布

配置不存放账号、密码、API Key、本机绝对路径或未经验证的 URL。生产配置通过环境变量或秘密管理注入敏感项，并采用 review、签名/哈希、灰度、回滚和审计流程。配置变化必须改变 catalog fingerprint，并触发受影响测试与证据刷新。
