# ADR-0001：官方编译器主线与兼容层边界

- 状态：已接受
- 日期：2026-08-09
- 决策范围：官方槽位 DSL 编译、兼容入口、扩展方式和后续清理

## 背景

项目早期通过手写 Lexer、Parser、Semantic 和 SQL Generator 快速建立了可运行基线，随后增加 ANTLR4 前端、强类型 AST、领域模型、关系 IR、规则优化、物理规划和 SQLGlot Doris 后端。迁移期间，部分新模块仍调用 `official_slot.py` 中的旧错误类型、字面量解析或指标解析帮助函数，导致“新架构在目录上存在，但运行时仍反向依赖旧入口”。同时，官方 5799 条语料曾被当成数千个独立修补任务，增加了硬编码和重复分支的风险。

## 决定

正式编译链固定为：

```text
OfficialSlot.g4
  -> ANTLR frontend
  -> immutable typed AST
  -> semantic policy binding
  -> domain model
  -> canonical relational IR
  -> equivalence rewrites
  -> physical candidate planning and cost selection
  -> validated physical IR
  -> SQLGlot Doris AST/SQL
  -> Doris execution and evidence
```

`src/findsl/official/` 是官方编译器的唯一正式实现边界。它不得依赖 `findsl.official_slot`、`findsl.compiler`、`findsl.parser`、`findsl.semantic` 或 `findsl.sqlgen`。共享错误、字面量和目录能力进入官方包内的独立模块；手写前端与双前端差分进入 `findsl.compat.official_frontend`。上述边界由 `import-linter` 在本地和 CI 中对整个 `findsl.official` 包强制检查。

旧管道暂时保留，用于兼容旧命令、历史差分和迁移回归，不再增加新业务语义。兼容层只能调用新核心，不能让新核心反向调用兼容层。移除旧管道必须等到正式正确率、12 类函数矩阵、零代码扩展、长周期自动优化和连续版本回归门禁通过。

官方语料的开发单位改为“能力族”，不是 Excel 行号。每个失败先归入解析、类型、业务语义、关系表达、物理能力、数据可用性或非法输入，再实现通用规则并批量回归。禁止按完整 DSL 文本、工作簿行号或证券名称添加生产分支。

## 理由

这一决定保留了已经验证的工程资产，同时停止继续扩大双管道和行级补丁债务。ANTLR 提供稳定语法前端，强类型模型使错误在生成 SQL 前暴露，关系 IR 支持可证明等价的重写，物理候选与成本选择满足长周期优化要求，SQLGlot 负责结构化 Doris SQL，Doris 自身的 Nereids、统计和物化视图承担数据库内优化。项目不复制完整 ANTLR、Calcite 或 Doris，而是在它们适合的边界复用成熟能力。

## 影响

- 新功能必须先判断属于配置目录、语义政策、关系算子、物理策略还是数据 Provider，不能直接写入大函数分支。
- `official_slot.py` 逐步收敛为兼容 facade，核心实现迁入 `src/findsl/official/`。
- `planner.py`、Doris backend 和验证器继续按候选规划、表达式翻译、范围绑定和安全校验拆分。
- 迁移覆盖率与 SQL 正确率继续使用不同名称、分母和证据。
- 无完整、版本化成员关系的数据范围返回结构化不可用诊断，不做模糊映射。

## 退出或替代条件

只有出现新的官方语法、目标数据库变化，或当前关系 IR 无法以可验证方式表达赛题核心语义时，才重新评估本决策。局部实现困难、单条语料失败或短期性能波动不构成推翻整体架构的理由。
