# 官方三表缺失数据域不可伪造 SQL 审计报告

生成时间：2026-07-06

## 1. 审计结论

本报告记录当前项目对官方真实数据的边界判断。结论很明确：项目已经可以完整解析官方 `选股提槽实例.xlsx` 中的 5799 条槽位 DSL，当前语法解析成功 `5799/5799`；在严格只使用官方三张 Doris CSV 及项目由三表确定性构建的特征表时，当前可落地编译为 Doris SQL 的样例为 `1882` 条。剩余 `3917` 条不能直接生成 SQL，主要原因不是解析器偷懒，而是官方当前数据包没有提供财务报表、基金持仓、指数成分、用户账户、自选股、龙虎榜、公司画像、题材热度、分钟级行情等数据域。

因此，项目必须坚持“不伪造 SQL”的原则。缺字段、缺表、缺时间粒度、缺排序依据时，应输出稳定错误码和可解释原因，而不是为了提高表面编译率生成 `1=1`、常数列、假表名或没有业务含义的排序。这种边界在金融科技赛题中非常关键：一个看似“覆盖率 100%”但内部夹杂伪 SQL 的系统，现场被追问字段来源时很容易失去可信度；一个明确区分可落地与不可落地的数据治理系统，反而更符合高质量工程交付。

## 2. 官方真实数据边界

当前比赛阶段可使用的官方真实数据包括三张 Doris CSV：

| 表 | 行数 | 主要数据域 |
|---|---:|---|
| `hsj_stock_code_info` | 5,686 | 股票代码、股票名称、市场标识、科创板/创业板/沪股通/深股通等代码表属性 |
| `hsj_stock_hq_basic` | 13,650,347 | 日频价格、成交量、成交额、盘口、涨跌停、估值、支撑压力、股本等行情基础字段 |
| `hsj_stock_hq_ext` | 6,170,822 | 资金流、集合竞价、涨速、创新高低、连涨连跌、破板、筹码形态等行情衍生字段 |

项目在 Doris 中还构建了由三表确定性派生的特征表，例如 `hsj_stock_hq_basic_prefix`、`hsj_stock_hq_ext_prefix`、`hsj_stock_hq_basic_technical`。这些表不是凭空补数据，而是由已有日频行情字段计算出的前缀和、均线、均量和技术形态辅助列，行数与基础行情骨架保持一致。

这意味着项目能够严谨支撑的范围主要是 A 股日频行情、基础代码属性、资金流和由这些字段可计算出的技术特征。它不能严谨支撑财报、基金、指数成分、用户账户、龙虎榜明细、新闻热度、主营业务、分钟级盘口序列等本批数据未提供的内容。

## 3. 当前覆盖率与失败分层

最新 `reports/official_slot_coverage.md/json` 结果如下：

| 指标 | 数值 |
|---|---:|
| 官方样例总数 | 5799 |
| 语法解析成功 | 5799 |
| 语法解析失败 | 0 |
| Doris SQL 编译成功 | 1882 |
| Doris SQL 编译失败 | 3917 |
| 全量样例可落地编译率 | 32.45% |

编译失败错误码如下：

| 错误码 | 次数 | 审计解释 |
|---|---:|---|
| `UNSUPPORTED_OFFICIAL_INDICATOR` | 3913 | 指标没有映射到官方三表或确定性特征表 |
| `UNSUPPORTED_OFFICIAL_COUNT_EXP` | 3 | 剩余出现/连续次数语义缺少排序依据或缺少数据域 |
| `UNSUPPORTED_OFFICIAL_PERIOD_FUNCTION` | 1 | 周期函数叠加聚合/缺失财务指标，当前三表不可落地 |

失败分层中数量最多的是“官方三表未覆盖的其他指标”“财务报表数据缺失”“公司画像与题材热度数据缺失”“指数成分与权重数据缺失”“基金产品与持仓数据缺失”。这些分类说明官方 workbook 是一个更宽的金融语义训练集，而本次真实 CSV 是 A 股日频行情数据包。二者不是一一覆盖关系，不能把训练语料中的所有金融意图都硬套到三张行情表上。

## 4. 已修复和归档的高价值缺口

本轮重点处理的是两类“可落地但此前没覆盖”的缺口。

第一类是 7 条官方 workbook 中的标点和残缺噪声。它们不是合法 DSL 语义本身的问题，而是 Excel 中出现了边缘引号、前导 `and`、多余右括号、孤立日期字面量等文本噪声。项目新增了输入标准化步骤：保留原始输入用于审计，同时在解析前修复这些可判定的表层噪声。修复后官方 workbook 语法解析从 `5792/5799` 提升到 `5799/5799`。

第二类是 14 条 `count_exp` 中可以由官方日频三表解释的部分。项目新增区间次数、连续区间、半年到月份桶归一、聚合计数表达等编译路径。修复后 `UNSUPPORTED_OFFICIAL_COUNT_EXP` 从 `14` 降到 `3`，可落地编译数从 `1873` 提升到 `1882`。这些新增 SQL 都基于真实字段、真实日期窗口和真实行级/桶级统计，不依赖假字段或常量凑数。

## 5. 剩余 3 条 `count_exp` 为什么不能伪造

剩余 3 条 `UNSUPPORTED_OFFICIAL_COUNT_EXP` 已逐条复核：

| Excel 行 | 官方问句 | DSL 摘要 | 不伪造原因 |
|---:|---|---|---|
| 1011 | 维持前二十地位上海市场主板票 | `rank('沪主板', '', '', 'desc', '', '', '', 'CONS>1') <= 20` | `rank` 没有指标名。没有排序字段时无法定义“连续维持前二十”的金融含义，不能用股票代码或名称顺序替代。 |
| 1037 | 高能电子+上海电网+科创股+化学剂，连着三年排 top10 的 | `rank('科创板', '高能电子&上海电网&化学剂', '', 'desc', '', '', '', 'CONS=3年') <= 10` | 同样没有排名指标。filter scope 只能限定范围，不能替代排序依据。 |
| 5257 | 营业收入比预测多，按这个排，今年连续三个季度都靠倒数二十 | `rank(... '营业收入' ... 'CONS=3季度') - rank(... '预测营业收入' ... 'CONS=3季度') > 0` | 需要营业收入、预测营业收入和季度级财务/预测数据。官方三张行情表没有这些字段，且 rank arithmetic 与 count_exp 组合需要财务时间桶排名。 |

这三条如果强行编译，会出现三种风险：用无意义排序替代真实排名、用不存在的财务字段生成假 SQL、把季度财务语义硬塞进日频行情表。项目当前选择返回错误码，是对官方数据边界负责。

## 6. 剩余 1 条周期函数为什么不能伪造

剩余 `UNSUPPORTED_OFFICIAL_PERIOD_FUNCTION` 来自 Excel 第 3631 行：

```text
record_high('科创板', '', '应收票据同比增长率', '近15日', '', '', 'MAX', '') = True
and indicator('科创板', '', '预收账款', '', '', '', '') >= indicator('科创板', '', '预收账款', '近30日', '', 'AVG', '')
```

该样例需要“应收票据同比增长率”和“预收账款”。这两个都是财务报表/资产负债相关指标，不在官方三张日频行情表中。即便 `record_high` 和 `AVG` 的语法能解析，底层字段也不存在；如果生成 SQL，只能依赖假字段或空表。因此当前保留不支持是正确选择。

## 7. 缺失数据域的可落地解决方案

如果后续赛题组或团队能够补充数据，应按数据域分层扩展，而不是在现有三表中硬凑。

| 缺失数据域 | 需要补充的数据 | 扩展方式 |
|---|---|---|
| 财务报表 | 利润表、资产负债表、现金流量表、预测财务指标、财报期维度 | 新增财务事实表，按 `mktcode/tgtcode/report_period` 建模，再补财务指标映射和季度/年度时间桶 |
| 基金产品与持仓 | 基金代码、基金类型、基金持仓、重仓股权重 | 新增基金产品表和持仓明细表，支持“基金十大重仓股”“基金类型”“跟踪指数” |
| 指数成分与权重 | 指数代码、成分股、权重、生效日期 | 新增指数成分历史表，支持成分股、权重排序、指数范围过滤 |
| 用户账户与自选股 | 用户持仓、自选分组、账户权限 | 新增用户侧权限数据表，答辩/提交时需注意隐私与脱敏 |
| 龙虎榜与交易异动 | 龙虎榜日期、席位、买入卖出金额、净流入 | 新增龙虎榜事实表，支持龙虎榜净流入和上榜日期 |
| 公司画像与题材热度 | 主营业务、概念标签、热门/龙头/潜力评分 | 新增画像标签表和热度评分表，必须标注数据来源和更新时间 |
| 分钟级行情 | 逐分钟成交、价格、盘口、集合竞价细节 | 新增分钟行情表，才能严谨支持 `CONS=10分钟` 等表达 |

扩展原则是“先有真实表，再有指标映射，再有 SQL 编译，再有 Doris evidence”。不能反过来先写 SQL，再假设数据以后会有。

## 8. 与性能证据的关系

不可伪造 SQL 审计不是降低性能目标，而是保护性能证据可信度。当前官方 Doris evidence 已经在真实导入的官方三表上记录了 6 条查询的逐问句矩阵：

| 查询类型 | P95 结果 | 说明 |
|---|---:|---|
| 普通价格过滤 | 47.384 ms | 单日价格条件和代码表连接 |
| 排名 TopN | 57.073 ms | 使用窗口/TopN 执行路径 |
| 技术特征过滤 | 61.269 ms | 使用 `hsj_stock_hq_basic_technical` |
| 资金流过滤 | 57.988 ms | 连接 `hsj_stock_hq_ext` |
| baseline 窗口滚动量 | 55.058 ms | 窗口路径 |
| prefix 优化滚动量 | 38.786 ms | 使用 prefix 特征表 |

这 6 条全部低于赛题 10 秒目标，最大 P95 为 `61.269 ms`。这些数据可以放进验收和答辩材料，因为它们来自真实 Doris evidence。相反，缺失财务/基金/账户数据域的 SQL 即便“生成”出来，也无法在当前 Doris 环境真实执行，不能作为性能证据。

## 9. 后续补强建议

短期内最有价值的工作不是追求 100% 编译率，而是继续提高可落地部分的现场抗质询能力：

1. 将当前 1882 条可编译样例按函数、指标、日期窗口、SQL 形态继续抽样审计，重点检查是否存在 `1=1` 过度放宽、日期窗口丢失、范围过滤遗漏等问题。
2. 对 `rank`、`record_high/record_low`、`position` 和复杂 `count_exp` 继续建立小规模物化特征表，但只覆盖字段来源明确的行情/资金/技术指标。
3. 将缺失数据域报告纳入答辩材料，明确说明“不能落地”是因为本批官方数据未提供，而不是系统无法解析。
4. 如果后续拿到财务、基金、指数成分或分钟级行情数据，再按表结构和字段来源补映射，不提前写假 SQL。

## 10. 答辩解释口径

可以这样回答评委追问：

“官方 workbook 有 5799 条槽位语料，我们已经全部解析成功。可生成 Doris SQL 的 1882 条都严格落在官方三张行情表或由这些表确定性派生的特征表上；剩余样例大量涉及财务、基金、指数成分、用户账户、龙虎榜、公司画像等数据域，而本次官方真实数据包没有这些表。金融场景里，生成一条没有字段来源的 SQL 比返回不支持更危险，所以系统会明确给出缺失数据域分类。我们追求的是可执行、可复现、可审计的 SQL，而不是表面 100% 覆盖。”
