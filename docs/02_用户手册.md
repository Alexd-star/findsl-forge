# 02 用户手册

本文档面向使用 FinDSL Forge 的比赛演示人员、评审体验人员和业务验证人员，说明如何输入需求、查看 DSL、查看 Doris SQL、理解验证结果和处理常见错误。更长篇的正式用户手册见 `docs/FinDSL_Forge_中文操作手册.md`。

## 1. 用户角色

| 角色 | 使用目标 | 主要入口 |
|---|---|---|
| 业务用户 | 输入中文筛选需求，查看系统生成的 DSL 和结果。 | Web Demo |
| 技术评审 | 查看 AST、Doris SQL、optimizer explain 和等价验证。 | Web Demo、CLI |
| 开发者 | 修改 DSL 能力、指标配置、测试和部署资产。 | CLI、源码、测试 |
| 答辩人员 | 演示正例、负例、性能证据和提交包。 | Web Demo、submission_artifacts |

## 2. Web Demo 使用

启动方式：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\serve_demo.ps1
```

启动后访问：

```text
http://127.0.0.1:8765
```

页面通常包含中文输入、DSL 候选、Doris SQL、AST、Explain、Rows、Evidence 和 Diagnostics 等区域。用户可以输入“筛选 A 股连续三天主力净流入为正并按换手率排名前一百”一类需求，系统会给出受控 DSL 候选。选择候选后运行分析，页面会展示编译结果和验证结果。

## 3. DSL 输入方式

用户也可以直接输入 DSL，例如：

```text
then(filter(market("A") & CONS(indicator("main_net_inflow") > 0, 3)), rank(indicator("turnover_rate"), desc, top=100))
```

这个表达式表示：先筛选 A 股中连续 3 个交易日主力净流入大于 0 的股票，再按每个交易日的换手率从高到低排名，取前 100。

## 4. 查看结果

运行后重点查看：

- `SQL`：编译器生成的 Doris SQL。
- `AST`：抽象语法树，用于证明系统理解的是结构化表达。
- `Explain`：优化规则和安全校验步骤，例如 `PREFIX_SUM`、`RANK_NULL_GUARD`、`DORIS_SQL_VALIDATION`。
- `Rows`：SQLite/reference 等价验证输出的结果行。
- `Evidence`：Doris 规模证据摘要。

## 5. 负例诊断

如果输入：

```text
filter(indicator("clos") > 10)
```

系统会提示未知指标，并给出接近的修复建议，如 `indicator("close")`。这证明系统不是简单报错，而是把错误转成可解释的诊断码和修复建议。

## 6. 使用注意事项

1. 自然语言入口只是辅助，最终执行必须通过 DSL 编译器。
2. 真实行情小样本用于业务可信展示，不用于 5M 行性能结论。
3. Doris 规模证据只应引用 `reports/doris_cluster_evidence.md` 或 `submission_artifacts/evidence_snapshots/doris_cluster_evidence.md` 中记录的口径。
4. 如果 Web Demo 暂时不可用，可使用 CLI 复现同样流程。
