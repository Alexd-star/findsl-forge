## 3. 本轮已完成开发

### 3.1 聚合排名 count_exp

已支持 `rank(..., agg_func, count_exp)` 的官方真实数据编译。实现路径为“股票-时间桶聚合值 -> 时间桶内排名 -> 命中桶统计”。例如：

```text
rank('', '', '成交量', 'desc', '近10日', '', 'GROWTH_RISE', 'CONS=10日') <= 20%
rank('', '', '集合竞价金额', 'asc', '2023年', '', 'AVG', 'CONS=每年') <= 10
```

生成 SQL 时，编译器会按 `count_exp` 单位调用 `DATE_TRUNC()` 形成日、周、月、季度或年桶；用 `AVG/SUM/MAX/MIN/MIN_BY/MAX_BY` 得到桶内聚合值；再用 `ROW_NUMBER() OVER (PARTITION BY bucket_key ORDER BY agg_value ...)` 排名；最后把排名条件交给 `CONS/EXIST` 计数逻辑。

### 3.2 穿越与金叉事件 count_exp

已支持 `cross_above/cross_down/golden_cross(..., count_exp)`。实现路径为“窗口内事件行 -> event_value -> count_exp 统计”。例如：

```text
cross_above('', '', '最新价', '60日均线', '近5日', '', 'CONS=每日') = True
golden_cross('', '', '5日均量线', '10日均量线', '近10个交易日', '', 'EXIST=2日') = True
```

编译器先在子查询中按股票和日期排序，使用 `LAG()` 取上一交易日左右两侧指标，再判断当日是否发生上穿、下穿或金叉。事件布尔值命名为 `event_value`，外层统一使用已有 `count_exp` 子查询处理“每日都满足”“出现 2 次”“连续 N 日”等语义。

### 3.3 官方口语日期归一化

已补充 `过去20天`、`30个交易日`、`三个月之内`、`近半年`、`近5个月至今`、`2024年8月`、`9号`、`九月十五号`、`本季度` 等官方口语时间表达。过去这些表达会退化为 `1=1` 并产生 runtime normalization warning，现在会生成明确日期窗口或明确无可满足行。例如以 2026-04-14 为官方锚点：

| 原文 | 归一化结果 |
|---|---|
| `过去20天` | `base.bizdate BETWEEN '2026-03-26' AND '2026-04-14'` |
| `30个交易日` | `base.bizdate BETWEEN '2026-03-16' AND '2026-04-14'` |
| `三个月之内` | `base.bizdate BETWEEN '2026-01-15' AND '2026-04-14'` |
| `近半年` | `base.bizdate BETWEEN '2025-10-14' AND '2026-04-14'` |
| `2024年8月` | `base.bizdate BETWEEN '2024-08-01' AND '2024-08-31'` |
| `9号` | `base.bizdate = '2026-04-09'` |
| `九月十五号` | 归一到 2026-09-15，但因超过官方锚点，被裁剪为 `1=0` |
| `本季度` | `base.bizdate BETWEEN '2026-04-01' AND '2026-04-14'` |

### 3.4 涨停价/跌停价与同义日期 scope

官方样例使用 `涨停价`、`跌停价`，真实基础行情表里对应字段是 `upSealPx`、`downSealPx`。本轮已经补充映射，并保留价格字段统一除以 `10000.0` 的单位换算。

同时，`count_exp` 表达式比较不再机械要求日期字符串完全一致。如果两个日期槽能无 warning 归一到同一 SQL 窗口，例如 `30个交易日内` 和 `30个交易日`，就允许放在同一个计数比较里。未知日期仍按原文区分，防止把“近期”“前期”这类模糊词误合并。

## 4. 剩余 16 条语义缺口拆解

| 类别 | 代表行 | 当前处理 | 判断 |
|---|---|---|---|
| 无指标排名叠加 count_exp | 1011、1037 | `rank(..., indicator_name='', count_exp)` 返回不支持 | 没有排名指标时无法定义“连续维持前二十”的排序口径，强行用代码排序没有金融意义 |
| 聚合 count_exp 嵌入四则表达式 | 1178 | `indicator(..., AVG, count_exp) / indicator(...) < ...` 返回不支持 | 可继续设计，但需要把“聚合后的每日值”作为临时表达式参与比较，属于下一轮可做项 |
| 小数/区间次数 | 1401、1887、2078、3206、3644、3769、4079、4287、4853 | `CONS=0.5年`、`CONS=1-2月`、`EXIST=2-5` 等返回不支持 | 官方说明只定义单次数和“每”，没有定义闭区间出现次数和连续长度范围，直接实现容易被评委问穿 |
| 分钟级语义 | 2439 | `CONS=10分钟` 返回不支持 | 官方真实表是日频，只有 3/5/10 分钟涨速字段，没有 9:15-9:25 逐分钟价格序列 |
| 缺财务字段的 period/aggregate | 3631 | `record_high(... 应收票据同比增长率 ..., MAX)` 返回不支持 | 应收票据、预收账款不在官方三表中 |
| 缺外部指标的数据域 | 2298、4079、4287、5257 等 | 控股股东、散户数量、龙头、热门、IOPV、营业收入、预测营业收入返回不支持 | 需要公司画像、账户、财务预测或基金净值数据，不属于当前真实包 |

建议下一轮只考虑“聚合 count_exp 嵌入四则表达式”这一类。它虽然复杂，但仍然基于外盘、每手股数等已有字段。其他项应继续保留显式边界，不建议用常数、近似标签或假表硬凑。

## 5. 后续开发计划

### 5.1 第一优先级：表达式级聚合 count_exp

目标：支持类似 `indicator('外盘', date, 'AVG', 'CONS=每日') / indicator('每手股数') < 80000` 的官方样例。

计划：

1. 写红测，覆盖 row 1178 中“后 3 日外盘均值 / 每手股数 < 80000 且 CONS=每日”的子表达式。
2. 在 `_count_exp_specs_from_node` 中允许带 `agg_func` 的 indicator 形成可统计表达式，但只限同一 market/filter/date/select/count_exp。
3. 新增表达式级 bucket 子查询：先按 date/count_exp 单位生成 `agg_value`，再把右侧普通 indicator 或常数重写到同一日期行。
4. 所有聚合表达式仍要求指标为官方三表或派生技术表可解释字段，不支持财务/基金/账户字段。
5. 跑 `tests/test_official_slot.py`、全量 pytest、official-slot-coverage，确认 count-exp 缺口下降。

### 5.2 第二优先级：日期 warning 精准下降

目标：继续补官方样例中明确可解释的日期表达，但不吞掉模糊词。

本轮已经补齐 `2024年8月`、`九月十五号`、`9号`、`近5个月至今`、`本季度`。后续可继续考虑 `收盘后`、`尾盘` 等交易阶段词，但这些词在日频 CSV 里没有盘中时间序列，默认不应转成具体分钟。`近期`、`最近`、`前期` 仍应保持 warning，因为没有明确窗口长度。

### 5.3 第三优先级：证据刷新
