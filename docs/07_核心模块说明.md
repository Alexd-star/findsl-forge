# 07 核心模块说明

本文档按模块说明“它是干什么的、输入是什么、输出是什么、和其他模块有什么关系”。

## 1. 编译器模块

涉及文件：`compiler.py`、`lexer.py`、`parser.py`、`semantic.py`、`sqlgen.py`。

输入是 DSL 字符串，输出是 `CompileResult`，其中包含 DSL、AST、Doris SQL、trace、structured explain 和耗时。该模块是系统主干，所有 CLI、Demo、LLM 验证和报告生成都会调用它。

## 2. 配置注册模块

涉及文件：`registry.py`、`configs/*.json`。

输入是配置文件，输出是 Registry 对象。它把函数、指标和表映射统一提供给 semantic、sqlgen、Doris asset generator 和测试。这个模块保证“新增指标不一定需要改编译器核心”。

## 3. 语义验证模块

涉及文件：`semantic.py`、`diagnostics.py`。

输入是 AST 和 Registry，输出是类型判断或诊断异常。它负责检查函数参数、窗口、rank 方向、日期格式、除零和非法字段。错误会被 `diagnostics.py` 转为稳定诊断码和修复建议。

## 4. SQL 生成与验证模块

涉及文件：`sqlgen.py`、`doris_sql.py`。

输入是通过语义校验的 AST，输出是 Doris SQL。SQL 生成后必须经过 `DORIS_SQL_VALIDATION`，确认只有单条 SELECT/WITH 查询、没有注释注入、没有 DDL/DML、没有未知表引用。

## 5. Reference 与等价验证模块

涉及文件：`reference.py`、`executor.py`、`equivalence.py`。

输入是 DSL 和 CSV 数据目录，输出是 SQL 与 reference 的结果差异。`reference.py` 用 Pandas 按 DSL 语义独立计算，`executor.py` 用 SQLite 执行生成 SQL，`equivalence.py` 比较行键。该模块是防止 SQL 生成误用的核心保险。

## 6. Doris 资产与证据模块

涉及文件：`doris.py`、`doris_evidence.py`、`deploy/doris/*`。

输入是配置、样本数据和 Doris 连接信息，输出是 DDL/SQL 文件、EXPLAIN、行数一致性和性能报告。它把项目从“本地编译器”推进到“可在 Doris 环境中验证”的工程证据。

## 7. AI 辅助模块

涉及文件：`nl2dsl.py`、`llm_adapter.py`、`llm_provider.py`。

输入是中文自然语言或 LLM 响应，输出是受控 DSL 候选及验证结果。它不会直接执行 LLM SQL，而是强制候选进入 compiler、SQL validator 和 reference oracle。

## 8. Web Demo 模块

涉及文件：`demo.py`。

输入是 HTTP 请求，输出是 HTML 页面或 JSON API。该模块用于答辩演示，可展示 DSL 候选、SQL、AST、Explain、Rows 和 Evidence。

## 9. 提交门禁模块

涉及文件：`readiness.py`、`defense_package.py`、`official_suite.py`。

输入是项目文件、样本、报告和 Git 状态，输出是 readiness report、defense package 和官方风格覆盖报告。该模块将测试、证据、提交物和回溯状态统一纳入交付判断。
