# 04 开发者文档

本文档面向继续开发 FinDSL Forge 的工程人员，说明代码组织、开发原则、常见改动路径和提交前检查。

## 1. 开发原则

1. 确定性核心优先。LLM 只能生成 DSL 候选，不能绕过 parser、semantic、SQL validator 和 reference oracle。
2. 配置扩展优先。新增指标优先修改 `configs/indicators.json`，不要直接硬编码到 SQL 生成器。
3. 语义一致优先。任何 SQL 改动都需要同步 reference 和 equivalence 测试。
4. 证据闭环优先。修改影响提交证据的内容后，应重新运行 readiness 并导出 submission artifacts。

## 2. 常见开发任务

### 新增指标

1. 在 `configs/indicators.json` 添加指标名称、表名、列名、类型。
2. 如果来自新表，在 `configs/tables.json` 添加逻辑表映射。
3. 补充 CSV 样本和测试。
4. 运行 `python -m pytest tests/test_config_extension.py tests/test_equivalence.py -q`。

### 新增 DSL 函数

1. 在 `configs/functions.json` 添加函数签名。
2. 在 `semantic.py` 定义类型规则。
3. 在 `sqlgen.py` 定义 SQL 生成规则。
4. 在 `reference.py` 定义 Pandas reference 语义。
5. 在 `tests/` 中补 parser、semantic、compiler、equivalence 测试。

### 修改 Doris SQL 生成

优先查看：

- `src/findsl/sqlgen.py`
- `src/findsl/doris_sql.py`
- `src/findsl/executor.py`
- `src/findsl/reference.py`
- `tests/test_compiler.py`
- `tests/test_equivalence.py`

修改后必须确认本地 SQLite 能执行生成 SQL。如果使用 Doris 支持但 SQLite 默认不支持的函数，需要在 `SQLiteSampleExecutor` 中注册兼容函数。

## 3. 测试命令

```powershell
python -m pytest -q
python -m pytest tests\test_equivalence.py -q
python -m pytest tests\test_compiler.py tests\test_doris_sql.py -q
powershell -ExecutionPolicy Bypass -File .\scripts\submission_readiness.ps1
```

## 4. 代码审查重点

- SQL 是否保持单语句 `SELECT/WITH`。
- Window 函数是否先物化再进入 outer WHERE。
- 日期下推是否保留窗口历史。
- 稀疏辅助表是否仍以 `daily_quote` 为骨架。
- `NULL/UNKNOWN` 语义是否与 SQL 三值逻辑一致。
- `rank(percent)` 是否只对非 NULL 排名值计数。
- 本地性能报告是否和 Doris 规模证据分开表述。

## 5. 提交建议

每次提交尽量围绕一个主题，例如：

```text
fix: align reference null semantics
feat: add return-rate DSL operator
docs: refresh submission evidence snapshots
```

如果代码改动会影响证据快照，建议分两次提交：先提交代码和测试，再在 clean 状态下生成 readiness/export 并提交证据。
