# 17 项目交付说明

本文档说明项目最终交付物、证据口径和提交前检查方式。

## 1. 核心交付物

| 交付物 | 路径 | 说明 |
|---|---|---|
| 项目入口 | `README.md` | 项目目标、快速启动和关键能力。 |
| 文件索引 | `PROJECT_INDEX.md` | 项目目录和文件作用总览。 |
| 更新日志 | `CHANGELOG.md` | 版本和变更记录。 |
| 源码 | `src/findsl/` | 编译器、验证器、Demo、证据生成。 |
| 配置 | `configs/` | 函数、指标、表映射。 |
| 测试 | `tests/` | 全量自动化测试。 |
| 样本数据 | `data/samples/`、`data/real_samples/` | 回归样本和真实行情小样本。 |
| Doris 资产 | `deploy/doris/` | DDL、样例数据、prefix 构建、smoke query。 |
| 中文文档 | `docs/` | 操作、架构、部署、测试、交付说明。 |
| 提交包 | `submission_artifacts/` | 技术报告、得分点、截图、视频、证据快照。 |
| 证据元数据 | `submission_artifacts/evidence_metadata.json` | 从 readiness、official suite 和 Doris evidence 抽取的机器可读指标总表。 |
| 证据摘要 | `submission_artifacts/evidence_summary.md` | 从元数据自动生成的可读摘要，适合评委快速核对核心数字。 |

## 2. 提交前检查

推荐执行：

```powershell
python -m pytest -q
powershell -ExecutionPolicy Bypass -File .\scripts\submission_readiness.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\export_submission_artifacts.ps1
git status --short
```

`submission_readiness.md` 中应重点确认：

- Blocking gates passed: True
- Warning count: 0
- Git rollback cleanliness: PASS
- Pytest 全量通过
- Official-style coverage suite 通过
- Doris-scale performance proof 通过

## 4. 交付口径注意事项

1. “真实行情样本”只证明业务字段和真实股票代码可运行，不证明 5M 性能。
2. “Doris 36.24x 加速”来自旧的 5M 合成规模 Doris evidence，只能按该 evidence 文件中的 DSL、数据规模和执行口径表述；官方真实 CSV 的证据必须以 `official_doris_evidence.md/json` 为准，两者不能混用。
3. “AI 辅助”是 NL2DSL/LLM 候选，不是直接执行大模型 SQL。
4. “企业级”表述应落在可审计、可测试、可部署、可回溯的工程实践上，不应夸大为已上线生产系统。
5. `evidence_metadata.json` 和 `evidence_summary.md` 只是结构化索引与可读摘要，不替代原始 Markdown/JSON 证据。若摘要、元数据和原始证据不一致，应以原始证据为准并重新执行导出脚本。
6. 官方 workbook 中未落地的样例，必须说明缺失数据域原因，例如财务报表、基金持仓、指数成分、用户账户、龙虎榜、主营业务和题材热度；不得用不存在的字段生成伪 SQL。

## 5. 人工确认事项

- 最终提交平台是否要求压缩包、GitHub 链接、视频或 PPT。
- 是否需要重新录制带人声的答辩视频。
- 是否需要在比赛平台现场重跑 Doris，还是提交离线 evidence 即可。
- 是否需要补充团队成员、学校、指导老师、版本号等封面信息。
