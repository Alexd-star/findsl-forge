# 08 算法说明

本文说明正式官方编译器的核心算法、正确性约束和优化边界。早期手写递归下降解析及内部 FinDSL SQL 生成只作为兼容实现，不代表当前正式算法。

## 1. 形式语法与解析

正式前端使用 ANTLR4。`grammar/OfficialSlot.g4` 定义词法、七槽位函数调用、比较、区间、算术、布尔复合、`then` 和限制结构。ANTLR 将文本解析为 parse tree，adapter 再构造不可变项目 AST，并保留源位置。

严格模式直接报告词法/语法错误；恢复模式只执行白名单文本规范化，记录原文、规范化结果和修复项。解析复杂度目标接近输入长度线性增长，同时通过最大输入长度、嵌套深度和节点数限制避免资源耗尽。

## 2. 类型推导与函数绑定

语义分析递归推导 numeric、boolean、time、string、range、relation 等类型，并按正式函数签名检查参数和槽位。比较运算要求类型兼容，`between` 必须使用显式范围，算术只接受数值，布尔组合只接受条件。指标由版本化 Registry 解析，找不到时返回 unknown 或结构化数据域诊断，不从旧编译器借用私有映射。

业务默认值不应隐藏在推导代码中。排名并列、复权、自然周期、近似阈值、位置分档、空值和范围历史有效性都要绑定 policy ID，使相同 DSL、目录和政策产生稳定 plan ID。

## 3. 领域语义降低

领域绑定把函数和槽位转换为指标表达、市场集合、时间范围、事件条件、排名和数据需求。它先回答业务含义，再降低为关系算子。新增能力优先组合已有正交算子，只有无法表达的新语义才增加领域节点。

数据缺失与算法不支持严格区分：缺少财务、基金、成员关系或分钟数据时返回 `*_DATA_UNAVAILABLE`；合法且有数据、但当前关系/物理计划不能表达时才是 capability gap。这样可以避免为了提高成功数生成空查询或伪 SQL。

## 4. 关系 IR

Logical IR 使用 Scan、Filter、Project、Join、Aggregate、Window、Rank、Stage 和 Set Operation 表达查询。节点不可变、可序列化并经过 validator。关系 IR 不包含 Doris 物理表和 SQL 文本，因此同一逻辑计划可以生成不同物理候选或在独立解释器中执行。

阶段筛选和排名通过显式 Stage/Rank 节点表达，窗口计算与输出日期过滤分离，避免 SQL 中 window function 直接进入同层 WHERE，也避免日期下推截断窗口预热数据。

## 5. 等价重写

每条逻辑规则只做语义等价变换，保存 rule ID、匹配条件、变换前后计划和证明义务。典型规则包括条件归一化、Project/Filter 合并、日期约束下推、重复表达式消除和集合表达式规范化。

规则正确性通过三类证据验证：小数据 reference 结果一致、Doris baseline/candidate 完整结果哈希一致、代数属性和反例测试。成本判断不写进规则，避免“为了快”改变语义。

## 6. 窗口与事件

固定观测窗口使用按证券、交易日排序的 Window。滚动和、平均、极值、连续/存在条件分别降低为 Aggregate/Window 或受控状态表达；前置历史行参与计算，但不一定进入最终输出。

日历区间、交易观测窗口和财报周期不能互相替代。`近三个月` 按日历边界，`60 日新高` 按有效交易观测，财报同比按报告期。停牌、上市前空窗、NULL 和除零均按版本化政策处理。

## 7. 排名

排名计划保存方向、分组键、稳定 tie-breaker、top/bottom/percent 和并列政策。当前默认可使用 `ROW_NUMBER` 并以证券稳定键打破并列，保证 Top N 不超过 N；由于官方未明确并列口径，该选择必须配置化并覆盖全并列、边界并列、空值和百分比排名。

百分比排名的分母只包含具有有效排名值的候选。任何没有 ORDER BY 的 LIMIT 都是非确定性结果，不能进入正确性证据。

## 8. 长周期候选

同一滚动语义可以枚举以下物理路径：

1. 原始 SQL window；
2. 固定窗口特征列；
3. prefix 当前值减前值；
4. 集合式 prefix CTE/Join；
5. rollup 服务表；
6. Doris 物化视图。

滚动求和与平均的基本公式为：

```text
rolling_sum(t, N) = prefix_sum(t) - prefix_sum(t-N)
rolling_count(t, N) = prefix_count(t) - prefix_count(t-N)
rolling_avg(t, N) = rolling_sum(t, N) / NULLIF(rolling_count(t, N), 0)
```

候选必须在同一数据快照上结果哈希一致。Phase 6C 证明集合式 prefix 路径相对相关标量子查询更好，但它相对固定技术特征列的中位加速仅约 `1.393x`；这不能替代另外工作负载中的 `40.52x`、`36.24x` 或 `13.99x` 长周期证据。

## 9. 成本与风险选择

候选成本应保留扫描字节、输出行、Shuffle、排序、窗口宽度、CPU、内存、数据新鲜度、历史 P95 和风险罚分等原始分量。统计来自 Doris ANALYZE、表/列统计和 Query Profile；统计缺失时必须标记估算或回退，不能伪装成实测。

当前规划器仍以规则顺序和有限静态成本为主。目标是引入轻量 memo：按逻辑等价类去重候选，等价规则负责产生候选，cost/risk selector 负责选择，Doris Nereids 继续负责数据库内部 Join 顺序、分区裁剪和执行优化。

## 10. SQL AST 与安全

Physical IR 通过 SQLGlot 生成 Doris AST，再渲染 SQL。安全校验要求单条 SELECT/WITH、表列白名单、无 DDL/DML、无注释逃逸、窗口位置合法、稳定排序和 Doris 方言往返一致。配置表达式只能使用受控代数，不能保存任意 SQL 模板后直接拼接。

## 11. 正确性算法

正式正确率比较完整、有序结果，不比较 SQL 字符串。oracle 分为 Pandas/SQLite 小数据解释、人工独立 Doris reference SQL 和代数变形测试。参考实现不复用被测 planner 或 renderer；空结果可以出现，但不能成为某函数唯一证据。

迁移率只说明新后端是否覆盖旧能力，不说明二者业务语义正确。最终 `>=95%` 必须在独立定义的 eligible 真值集上计算，并按 12 类函数和计划族报告分层结果。

## 12. AI 边界

AI 只生成 DSL 候选、解释诊断或辅助文档。候选必须通过相同语法、类型、IR、物理规划和 SQL 安全门禁；AI 不参与正式 oracle，不直接执行 Doris SQL，也不是赛题核心编译算法。
