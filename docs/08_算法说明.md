# 08 算法说明

本文档说明 FinDSL Forge 中的核心算法和语义口径。

## 1. DSL 解析算法

项目使用手写词法分析和递归下降解析。词法分析把字符串拆分为标识符、字符串、数字、括号、比较符、布尔符和命名参数符号；解析器再把 token 组合成 AST。这样做的好处是规则可控、错误位置清楚、依赖少。

## 2. 语义分析算法

语义分析采用递归类型检查。每个 AST 节点返回 `numeric`、`boolean`、`relation`、`order` 等类型。比较表达式要求两侧为数值；`filter` 要求布尔条件；`rank` 要求数值表达式和排序方向；窗口函数要求正整数窗口。这个过程在 SQL 生成前拦截非法表达。

## 3. SQL 生成算法

SQL 生成器按照关系表达式生成嵌套查询或 CTE。窗口特征先在内层 select 中物化，再由外层 WHERE 过滤，避免 window function 直接出现在 WHERE 中。`then` 会被编译成 staged CTE pipeline，使多阶段筛选和排名具有明确边界。

## 4. 排名算法

`rank(expr, desc, top=N)` 和 `rank(expr, asc, bottom=N)` 使用 `ROW_NUMBER() OVER (PARTITION BY trade_date ORDER BY expr, ts_code ASC)`。其中 `ts_code ASC` 是稳定 tie-breaker，避免相同指标值时结果不确定。

`percent=N` 使用 `COUNT(*) OVER (PARTITION BY trade_date)` 计算有效排名分母，并用 Doris `CEIL((__partition_count * N) / 100.0)` 得到阈值。系统会先排除 rank 表达式为 NULL 的行，使百分比排名只作用于有效指标值。

## 5. 窗口算法

`MA/SUM/MAX/MIN` 映射为 SQL window function，窗口范围为 `ROWS BETWEEN N-1 PRECEDING AND CURRENT ROW`。`CONS` 使用滚动 `SUM(CASE WHEN condition THEN 1 ELSE 0 END)` 判断连续满足；`EXIST` 使用滚动 `MAX(CASE WHEN condition THEN 1 ELSE 0 END)` 判断窗口内是否存在。

## 6. 收益率算法

`RET(value, n)` 定义为当前值除以 n 个交易日前的值再减 1。SQL 使用 `LAG(value, n)`，并通过 `NULLIF(previous, 0)` 防止除零。reference oracle 使用 Pandas groupby shift 独立解释。

## 7. Prefix-Sum 优化算法

对支持 prefix-sum 的指标，滚动和可改写为：

```text
rolling_sum(N) = current_prefix - prefix_at_row_no_minus_N
```

如果配置了热点窗口物化列，例如 `volume_sum_120`，则直接读取该列，减少 query-time self join。这个优化适合长窗口累计指标，最终性能结论以 Doris EXPLAIN 和集群 latency 证据为准。

## 8. 日期下推算法

无窗口条件可以把完整日期范围下推到 base scan；窗口条件只下推安全上界，避免截断历史窗口；prefix-sum 可在当前行范围下推完整日期，因为历史值由 prefix row_no 查找提供。

## 9. SQL 三值逻辑

SQL 中 `NULL` 比较结果是 UNKNOWN。WHERE 只保留 TRUE，UNKNOWN 不会通过。reference oracle 已对比较、`AND/OR`、连续/存在窗口和 rank NULL 过滤做相应处理，避免 Pandas 默认布尔行为与 SQL 不一致。
