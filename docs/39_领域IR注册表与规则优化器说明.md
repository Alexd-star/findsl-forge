# 领域 IR、官方指标注册表与规则优化器说明

## 1. 建设目的

Phase 3 已经形成 Typed AST 和 SQL-free Logical IR，但 `indicator`、`cross_above`、`record_high` 等函数仍主要表现为通用 CallExpr。Phase 4 增加领域绑定层，把函数槽位解释成指标、市场、日期、事件和数据需求，并在验证后的逻辑计划上运行可审计规则。

新链路仍处于 shadow 模式，不替换 `official-slot-compile`。它的作用是为下一阶段物理绑定和 Doris backend 提供稳定输入，而不是提前复制旧 SQL 生成代码。

## 2. 官方指标注册表

注册表位于 `configs/official/indicators.json`，结构约束位于 `indicators.schema.json`。当前共收录 1,177 个规范指标：101 个来自官方基础字段，96 个可由已有行情计算，980 个在官方工作簿中出现但官方三张数据表没有提供。

缺失指标仍然进入注册表，因为“已知但数据缺失”和“系统完全不认识”是两种不同情况。Binder 对前者返回 `DOMAIN_DATA_UNAVAILABLE`，对真正未登记的名称返回 `DOMAIN_UNKNOWN_INDICATOR`。缺失条目不包含 physical hint，也不会转换成 Empty relation 或 SQL `1=0`。

迁移脚本 `scripts/migrate_official_registry.py` 从 legacy 静态指标和官方工作簿重建目录。它会合并 `CCI/cci` 等大小写变体，校验类型冲突，并按照财务、基金、指数、账户、概念、异常交易等数据域分类。

## 3. 领域绑定

`official/domain/binder.py` 使用 Typed AST 的精确函数签名读取槽位。指标被绑定为 `IndicatorRef`，市场绑定为 `MarketScope`，日期绑定为 `DateConstraint`，交叉、重合和重置函数绑定为 `EventSpec`，同时计算 `DataRequirement`。

Binder 覆盖 12 类官方函数，并区分未知指标、缺失数据域、非法枚举、无法绑定的空指标和尚未支持的能力组合。错误包含函数名、槽位名和值，便于在 Web Demo 和答辩证据中定位。

## 4. 领域关系节点

Logical IR 增加 DomainScan、Event、Consecutive、Exist、DomainRank、Constraint 和 Empty 节点。节点只表达逻辑含义，不保存 Doris 表名、SQL expression 或 join alias。LogicalEmpty 只接受 `PROVEN_` 开头的证明理由，缺失数据与解析失败不能伪装为空结果。

## 5. 规则优化器

默认规则集按固定顺序执行：

1. `BOOL_FLATTEN`：在不改变操作数顺序的前提下规范布尔结合方式；
2. `CONST_FOLD`：折叠纯字面量表达式；
3. `PREDICATE_DEDUP`：依据内容哈希删除重复 AND/OR 谓词；
4. `CONSTRAINT_MERGE`：合并 market 和明确日期约束，证明冲突时生成 LogicalEmpty；
5. `FILTER_PUSH_DOWN`：只把纯行级谓词越过声明式 Constraint，下推不跨 rank、window 或 stage；
6. `FILTER_MERGE`：合并相邻 Filter；
7. `STAGE_NORMALIZE`：只重编号 stage 元数据，不改变操作；
8. `LIMIT_NORMALIZE`：按关系切片语义组合 offset/count；
9. `RANK_CONTRACT_NORMALIZE`：规范方向大小写和一元正号。

每次规则命中记录 rule ID、版本、before/after hash、节点路径、耗时和 proof obligation。优化器每批修改后重新运行 IR validator；若规则异常或计划失效，返回原计划和诊断，不暴露部分修改结果。空规则集可以完全关闭优化。

## 6. 等价性验证

小数据解释器独立执行 Scan、Filter、Limit 和 Empty 子集。当前生产规则在覆盖子集上比较优化前后股票行键，要求精确一致。除此之外，测试还检查确定性、幂等、规则关闭、嵌套 limit 语义、约束交集和 stage 重编号。

解释器尚未覆盖 Window、Rank、Event 和 Consecutive 的完整金融时间语义，因此这些节点不执行激进重写。后续扩展规则前必须先扩展独立解释器或 Doris 行集差分证据。

## 8. 当前证据口径

最新审计中，领域 lowering 成功计划全部通过优化后验证，优化器诊断和幂等差异均为 0，bind 与 optimize P95 低于 5 ms。大量失败已从笼统“未知指标”改为明确的 `DOMAIN_DATA_UNAVAILABLE`，这说明系统理解问句中的指标，但不会伪造官方未提供的数据。

领域计划成功数、规则命中数和注册表命中率都不是 SQL 正确率。现阶段仍以 strict SQL 1,097 条作为 grounded 编译基线，结果正确率必须等待 Phase 5 backend、真实 Doris 执行和独立参考结果比较。

## 9. 下一阶段

Phase 5 应建立 Logical/Domain IR 到 Doris SQL AST 的新后端，引入 SQLGlot Doris 方言校验，并为基础扫描、技术特征、前缀表和快照表建立物理候选。代价模型只选择项目特有路径，不复制 Doris Nereids CBO。所有新后端结果应与旧 SQL 或独立解释器进行行集差分后再进入默认链路。
