# 05 自动测试结果解释与人工核验流程

## 1. 当前自动测试结果逐行解释

当前最推荐打开的证据文件是：

```text
submission_artifacts/evidence_summary.md
```

其中核心内容如下：

```text
Blocking gates: PASS
Warning count: 0
Pytest regression: 197 passed in 14.13s
Official positive cases: 37/37
Official negative diagnostics: 37/37
Defense package checks: 13/13
Doris evidence: PASS
Doris cluster speedup: 36.24x
Doris row parity: PASS
Git HEAD at report generation: be2ea88
Git HEAD at export: be2ea88
Metadata Warnings: <none>
```

### 1.1 Blocking gates: PASS

中文意思是“阻塞门禁通过”。阻塞门禁就是项目认为必须通过的检查，例如自动测试、编译正确性、SQL/reference 等价验证、官方套件、Doris 资产完整性等。

它证明：项目当前没有在必须项上失败。它不能证明：项目已经覆盖所有真实业务场景，也不能证明比赛现场环境一定不出问题。

复现方式：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\submission_readiness.ps1
```

截图要求：截 `Decision Summary` 和 `Gate Matrix` 开头部分，必须包含 `Blocking gates passed: True`。

答辩解释：  
“Blocking gates 是我们提交前的自动门禁，覆盖测试、编译、等价验证、官方套件和证据文件。当前结果为 PASS，说明核心提交条件全部满足。”

### 1.2 Warning count: 0

中文意思是“警告数量为 0”。warning 不是必然阻塞提交的错误，但会提示风险，例如 Git 工作区不干净、Doris 规模证据缺失等。

它证明：当前 readiness 没有发现未关闭的警告。它不能证明：未来修改代码后仍然没有 warning。

复现方式同 readiness。截图要求：截 `Warning count: 0`。

答辩解释：  
“warning 为 0 说明当前证据快照对应的是一个干净、可提交的状态，不是带未提交代码或缺失 Doris 证据的中间状态。”

### 1.3 Pytest: 197 passed

中文意思是“197 个 pytest 自动测试全部通过”。pytest 是 Python 自动化测试工具，项目里的测试文件在 `tests/` 目录。

它证明：已写入测试集合中的 197 个断言全部通过。它不能证明：没有任何未测试场景，也不能替代人工演示。

复现方式：

```powershell
$env:PYTHONPATH="src"
python -m pytest -q
```

截图要求：截终端最后 5 行，必须包含 `197 passed` 或全量点阵输出结束部分。

答辩解释：  
“197 passed 说明项目有自动回归测试，覆盖 parser、semantic、compiler、equivalence、Doris evidence、Demo、readiness 和证据元数据等模块。”

### 1.4 官方正例：37/37

官方正例是“应该成功”的题目。比如正常的选股条件、排名、日期范围、收益率、prefix-sum 等。37/37 表示 37 个正例全部通过。

它证明：项目对一批官方风格正常题有覆盖，并且这些题能编译、验证并匹配 reference。它不能证明：所有官方可能题目都已经覆盖。

复现方式：

```powershell
$env:PYTHONPATH="src"
python -m findsl.cli official-suite --json
```

截图要求：截 JSON 输出里的 `positive_passed` 和 `positive_total`，或打开 `submission_artifacts/evidence_snapshots/official_suite_report.md` 截 Summary。

答辩解释：  
“正例通过说明正常业务需求能够进入编译和等价验证流程。”

### 1.5 官方负例：37/37

官方负例是“应该失败并给出诊断”的题目，比如未知指标、错误函数、窗口不是正整数、日期倒置、直接 SQL 风险等。

它证明：系统不是只会处理正确输入，也能稳定拒绝错误输入。它不能证明：所有恶意输入都已经覆盖。

复现方式同 official-suite。截图要求：截 `Negative diagnostic cases passed: 37/37`。

答辩解释：  
“负例通过说明系统具备安全边界和修复提示，不会把错误 DSL 或危险输出直接送进 Doris。”

### 1.6 Doris evidence: PASS

Doris evidence 是 Doris 集群证据，包含 EXPLAIN、延迟、行数一致性和加速比。

它证明：项目保存的 Doris 证据满足 readiness 门禁，baseline 和优化 SQL 都成功，行数一致，且加速达到目标。它不能证明：所有查询都能 36.24x，也不能证明任意机器重跑一定同样快。

复现方式分两种：

1. 查看现有证据：

```text
submission_artifacts/evidence_snapshots/doris_cluster_evidence.md
```

2. 现场重跑，需 Doris 环境：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\collect_doris_evidence.ps1
```

截图要求：截 `Evidence passed: True`、`Row counts match: True`、`Doris cluster speedup: 36.24x`。

### 1.7 Doris speedup: 36.24x

意思是优化 SQL 比 baseline SQL 快约 36.24 倍。当前证据对应的是特定 DSL：

```text
filter(SUM(indicator("volume"), 120) > 1000000)
```

它证明：在保存的 5,000,000 行 Doris 证据下，120 日成交量长窗口 prefix 路径达到 10x 以上目标。它不能证明：所有查询、所有指标、所有环境都有同样加速。

答辩解释要谨慎：  
“36.24x 是针对 120 日成交量滚动 SUM 的 Doris 证据，不泛化到所有选股条件。它证明项目对赛题最关注的长窗口场景有可复核加速证据。”

### 1.8 Git HEAD: be2ea88

Git HEAD 是证据生成时对应的代码提交版本。`be2ea88` 是短提交号。

复现方式：

```powershell
git log --oneline -1
```

截图要求：截 `git log --oneline -3`，能看到当前提交和提交说明。

答辩解释：  
“我们把证据和代码版本绑定，避免出现报告说通过但代码已经变了的情况。”

### 1.9 Metadata warnings: <none>

意思是证据元数据解析时没有发现缺文件、JSON 错误或 Doris 证据缺失。

复现方式：

```powershell
$env:PYTHONPATH="src"
python -m findsl.cli evidence-metadata --snapshots-dir submission_artifacts/evidence_snapshots --output submission_artifacts/evidence_metadata.json --summary-output submission_artifacts/evidence_summary.md
```

截图要求：截 `evidence_summary.md` 末尾 `Metadata Warnings - <none>`。

## 2. 人工验收流程

下面这套流程是给你“照着做”的。建议每一步完成后截图，截图文件名按 `06_界面截图证据与功能核验表.md` 的建议保存。

### 步骤 1：进入项目目录

在哪里操作：PowerShell。

命令：

```powershell
cd D:\Luo_docs\竞赛\研创赛\研究生金融科技创新大赛\findsl-forge
```

正常现象：命令行路径切换到项目根目录。失败现象：提示路径不存在，说明文件夹位置不对。

通过标准：`dir` 能看到 `README.md`、`src`、`tests`、`submission_artifacts`。

### 步骤 2：确认 Git 状态

命令：

```powershell
git status -sb
git log --oneline -3
```

正常现象：显示 `main...origin/main`，最近提交能看到 `12b29e4`、`be2ea88` 等。失败现象：显示大量未提交修改，说明当前文件和证据可能已经变化。

截图位置：终端。

通过标准：工作区干净，或你能解释哪些文件是你刚刚生成的。

### 步骤 3：运行全量自动测试

命令：

```powershell
$env:PYTHONPATH="src"
python -m pytest -q
```

正常现象：最后显示 `197 passed`。失败现象：出现 `FAILED`、`ERROR` 或非 0 退出。

失败时先检查：`tests/` 中失败测试对应的源码文件，例如 `test_compiler.py` 对应 `compiler.py/sqlgen.py`。

### 步骤 4：运行官方正负例套件

命令：

```powershell
$env:PYTHONPATH="src"
python -m findsl.cli official-suite --json
```

正常现象：JSON 中 `passed: true`，`positive_passed: 37`，`positive_total: 37`，`negative_passed: 37`，`negative_total: 37`。

失败时检查：`data/samples/official_positive_cases.jsonl`、`data/samples/official_negative_cases.jsonl`、`src/findsl/official_suite.py`。

### 步骤 5：运行一个编译样例

命令：

```powershell
$env:PYTHONPATH="src"
python -m findsl.cli compile 'filter(SUM(indicator("volume"), 120) > 1000000)' --json
```

正常现象：输出 JSON，里面有 `sql`、`trace`、`explain`、`elapsed_ms`。

截图必须包含：DSL、SQL、explain 中与 prefix 或 validation 有关的字段。

### 步骤 6：运行 SQL/reference 等价验证

命令：

```powershell
$env:PYTHONPATH="src"
python -m findsl.cli verify-sql 'filter(SUM(indicator("volume"), 3) > 300)' --data-dir data/samples --json
```

正常现象：`passed` 为 true，missing 和 extra 为空。

失败时检查：`src/findsl/equivalence.py`、`reference.py`、`executor.py`、`sqlgen.py`。

### 步骤 7：运行负例诊断

命令：

```powershell
$env:PYTHONPATH="src"
python -m findsl.cli diagnose 'filter(indicator("clos") > 10)' --json
```

正常现象：命令退出码可能为 1，但 JSON 中应包含 `UNKNOWN_INDICATOR` 和建议。这个退出码不是坏事，因为它在证明错误输入被拒绝。

截图必须包含：错误码、suggestions。

### 步骤 8：启动 Web Demo

命令：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\serve_demo.ps1
```

然后浏览器打开：

```text
http://127.0.0.1:8765
```

正常现象：页面出现 FinDSL Forge Demo，可输入中文或选择样例。失败现象：端口占用或 Python 报错。

失败时检查：`src/findsl/demo.py`、`scripts/serve_demo.ps1`，必要时换端口运行 CLI。

### 步骤 9：查看证据摘要

打开：

```text
submission_artifacts/evidence_summary.md
```

正常现象：能看到 PASS、warning 0、197 passed、37/37、36.24x、Git HEAD。

通过标准：这些数字和 readiness 快照一致。

### 步骤 10：导出提交包证据

命令：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\export_submission_artifacts.ps1
```

正常现象：终端输出 Manifest、Metadata、Summary 路径。

通过标准：`submission_artifacts/evidence_summary.md`、`evidence_metadata.json`、`evidence_snapshots/` 更新成功。
