# 02 项目结构与运行流程

## 1. 项目结构总览

项目根目录下最重要的文件和文件夹如下。这里先讲你必须认识的主线文件，完整索引可以继续看根目录 `PROJECT_INDEX.md`。

| 路径 | 类型 | 作用 | 你要重点看什么 |
|---|---|---|---|
| `README.md` | 项目入口文档 | 说明项目是什么、怎么启动、核心能力是什么 | 快速启动命令、核心能力列表 |
| `PROJECT_INDEX.md` | 文件索引 | 说明主要文件和目录作用 | 不知道某个文件干什么时先查这里 |
| `CHANGELOG.md` | 更新日志 | 记录近期修复和证据刷新 | 看最近测试数、修复点 |
| `pyproject.toml` | Python 配置 | 声明包名、Python 版本、pytest 配置 | `pythonpath = ["src"]` |
| `configs/` | 配置目录 | 函数、指标、表映射 | 新增指标主要改这里 |
| `src/findsl/` | 源码目录 | 编译器、验证器、Demo、Doris 证据 | 项目核心 |
| `tests/` | 测试目录 | 203 项自动测试来源 | 出问题时看对应测试 |
| `data/samples/` | 小样本数据 | 本地测试、官方正负例、Demo 默认数据 | CSV 和 JSONL |
| `data/real_samples/` | 真实行情样本 | 东方财富公开 A 股样本 | 业务可信展示 |
| `data/generated/` | 生成的大数据 | Doris 规模实验数据 | 很大，不建议提交 |
| `deploy/doris/` | Doris 部署资产 | DDL、样例数据、prefix 表构建 | Doris 环境复现 |
| `scripts/` | 脚本目录 | 一键运行测试、证据、Demo、导出 | 你日常操作主要跑这里 |
| `reports/` | 本地报告输出 | readiness、Doris evidence、临时报告 | 本地生成，不是提交入口 |
| `submission_artifacts/` | 提交包 | 可提交、可回溯的证据和截图 | 答辩前重点看 |
| `docs/` | 文档目录 | 操作手册、架构、测试、部署说明 | 深入理解项目 |
| `项目全流程导师文档/` | 本文档夹 | 从零学习和答辩陪练材料 | 你现在主要读这里 |

## 4. 人话版运行流程

如果你只是想理解系统怎么工作，可以记住下面这条线：

1. 用户输入一句选股条件，可以是 DSL，也可以是中文需求。
2. 如果是中文，系统先把它变成候选 DSL。
3. 编译器读取 DSL，检查它是不是合法。
4. 合法后，系统把 DSL 翻译成 Doris SQL。
5. 如果涉及长窗口求和，系统尽量用 prefix-sum 优化，让 Doris 少算很多重复窗口。
6. 系统用本地参考实现和 SQLite 执行结果做对比，确认 SQL 没有编错。
7. Doris evidence 用真实 Doris 环境证明性能加速。
8. readiness 把所有测试、报告、性能证据和 Git 状态汇总成提交前结论。

## 5. 技术版运行流程

```text
DSL 字符串
  -> lex(source)
  -> Parser(source).parse()
  -> SemanticAnalyzer(registry).validate(ast)
  -> SqlGenerator(registry, enable_prefix_sum=True).generate(ast)
  -> validate_doris_select_sql(sql, registry)
  -> CompileResult(dsl, ast, sql, trace, explain, elapsed_ms)
```

如果执行等价验证，则继续：

```text
CompileResult.sql
  -> SQLiteSampleExecutor(data_dir).execute(sql)
DSL
  -> PandasReferenceEvaluator(data_dir).evaluate(dsl)
SQL keys 与 reference keys 比较
  -> EquivalenceResult(passed, missing_keys, extra_keys)
```

如果执行 readiness，则继续：

```text
pytest
official-suite
evaluate
verify-sql
benchmark-prefix-sum
demo smoke
nl2dsl smoke
llm safety smoke
doris evidence marker check
git clean check
  -> submission_readiness.md
  -> evidence_metadata.json
  -> evidence_summary.md
```

## 6. 文件/函数调用链

### 6.1 CLI 编译调用链

```text
python -m findsl.cli compile '<DSL>'
  -> src/findsl/cli.py main()
  -> Compiler().compile(dsl)
  -> parse(dsl)
  -> SemanticAnalyzer.validate(ast)
  -> SqlGenerator.generate(ast)
  -> validate_doris_select_sql(sql)
  -> print SQL / JSON
```

### 6.2 SQL/reference 等价验证调用链

```text
python -m findsl.cli verify-sql '<DSL>' --data-dir data/samples
  -> cli.py main()
  -> verify_sql_equivalence(dsl, data_dir)
  -> Compiler.compile(dsl)
  -> SQLiteSampleExecutor.execute(compiled.sql)
  -> PandasReferenceEvaluator.evaluate(dsl)
  -> 比较 ts_code + trade_date
  -> 输出 missing / extra
```

### 6.3 readiness 调用链

```text
powershell -File scripts/submission_readiness.ps1
  -> python -m findsl.cli readiness-report
  -> generate_readiness_report()
  -> _run_pytest()
  -> evaluate_file()
  -> verify_sql_equivalence()
  -> benchmark_prefix_sum_file()
  -> run_official_suite()
  -> generate_defense_package()
  -> _git_state()
  -> reports/submission_readiness.md
```

### 6.4 Web Demo 调用链

```text
powershell -File scripts/serve_demo.ps1
  -> python -m findsl.cli serve-demo
  -> run_demo_server()
  -> 浏览器打开 http://127.0.0.1:8765
  -> POST /api/suggest 或 POST /api/analyze
  -> suggest_from_text() / analyze_dsl()
  -> Compiler.compile()
  -> verify_sql_equivalence()
  -> 页面展示 DSL、SQL、AST、Explain、Rows、Evidence
```
